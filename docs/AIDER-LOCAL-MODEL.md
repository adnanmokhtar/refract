# Running the setup on a local model via Aider (llama.cpp)

Use a **local GGUF model** (free, on your machine) as the brain, **Aider** as the driver
(edits files + git), and **this repo's setup** (rules + knowledge + commands) as the
discipline. Tested target: Mac mini M4, 24 GB; model
`yuxinlu1/gemma-4-12B-coder-fable5-composer2.5-v1-GGUF:Q4_K_M` (~7.4 GB).

> **Why not `llama-cli` directly?** `llama-cli` only chats — it can't edit files, run git,
> or load `.claude/`. Aider can. So you run the model as a *server* and point Aider at it.
> See `ai/references/models.md` — the setup runs on a **driver**, the model is just the engine.

---

## 0. Install (once)

```bash
# Homebrew (skip if installed)
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# llama.cpp (gives llama-cli + llama-server) and Aider
brew install llama.cpp
python -m pip install aider-install && aider-install

# verify
llama-cli --version
aider --version
```

## 1. Download the model (once — it caches)

```bash
llama-cli -hf yuxinlu1/gemma-4-12B-coder-fable5-composer2.5-v1-GGUF:Q4_K_M
```
Wait for the ~7.4 GB download, let it start chatting, then `Ctrl+C`. It's cached now — you
never download it again. *(If `-hf` isn't supported on your llama.cpp, download the `.gguf`
manually and use `-m /path/to/model.gguf` everywhere below instead of `-hf …`.)*

## 2. Start the model as a server — **Terminal 1** (leave running)

```bash
llama-server \
  -hf yuxinlu1/gemma-4-12B-coder-fable5-composer2.5-v1-GGUF:Q4_K_M \
  -ngl 999 \        # offload all layers to Metal (M4 GPU)
  -c 16384 \        # context window — big enough for the rules + knowledge
  --port 8080
```
This exposes an OpenAI-compatible API at `http://localhost:8080/v1`.

## 3. Verify the server — Terminal 2

```bash
curl http://localhost:8080/v1/models   # should return JSON
```

## 4. Wire THIS repo's setup into the project (once per project)

Aider does **not** read `.claude/` on its own. Generate the Aider bridge so it loads the
rules + knowledge + command procedures. In a **Claude Code** session inside the project:

```bash
cd /path/to/your/project
/setup-project --add-tool=aider
```
This writes:
- `CONVENTIONS.md` — your project's flattened discipline + the command procedures, with an
  **EXECUTE NOW** preamble (so `/commands` run instead of being treated as reference).
- `.aider.conf.yml` — with a `read:` list pulling in `CONVENTIONS.md`, `ai/_session-digest.md`,
  the foundational rules, etc.

*(No Claude Code? Create `.aider.conf.yml` by hand using the template in step 5, and copy
the rules you care about into `CONVENTIONS.md`.)*

## 5. Add the local-model lines to `.aider.conf.yml`

Merge these three groups into the generated `.aider.conf.yml`:

```yaml
# --- point Aider at the local server ---
openai-api-base: http://localhost:8080/v1
openai-api-key: dummy            # required by Aider; llama-server ignores the value
model: openai/local              # openai/ prefix = "OpenAI-compatible endpoint"; name is a label

# --- tuning for a small local model ---
edit-format: diff                # if edits come out garbled, switch to: whole
auto-commits: false              # review before it commits (safer with a 12B model)
show-model-warnings: false       # silence "unknown context window/pricing" noise

# --- the setup bridge (generated by --add-tool=aider; keep it) ---
read:
  - CONVENTIONS.md
  - ai/_session-digest.md
  - .claude/rules/read-before-write.md
  - .claude/rules/code-quality.md
  - ai/conventions.md
```

## 6. Run — Terminal 2

```bash
cd /path/to/your/project
aider
```
Aider connects to your local Gemma model **and** follows the setup's rules/knowledge.

## Daily usage (no re-download)

```bash
# Terminal 1 — model server
llama-server -hf yuxinlu1/gemma-4-12B-coder-fable5-composer2.5-v1-GGUF:Q4_K_M -ngl 999 -c 16384 --port 8080

# Terminal 2 — work
cd /path/to/project && aider
```

## What works on a 12B local model (expectations)

| Works well | Avoid (needs a stronger model) |
|---|---|
| Single-file edits, small refactors | `/audit`, `/optimize`, `/migrate` (heavy multi-agent sweeps) |
| `fix-bug`, `add-endpoint`, light `add-feature` | Large multi-file features in one shot |
| Following `CONVENTIONS.md` + rules as context | Tool-calling-heavy flows |
| Implementing from a `--plan` / spec you paste in | — |

The `ai/` knowledge layer and rules are plain markdown — usable regardless of model.
Keep `CONVENTIONS.md` tight: Aider reloads it every session, and a small model has limited context.

## Troubleshooting

| Symptom | Fix |
|---|---|
| Edits come out malformed / not applied | set `edit-format: whole` (more reliable for small models) |
| "model not found" / context-window warnings | harmless — `show-model-warnings: false`; the `openai/` prefix + base URL is the working pattern |
| `-hf` unsupported | download the `.gguf` manually, use `-m /path/to/model.gguf` |
| Slow / runs out of memory | lower `-c` (e.g. `-c 8192`) or use a smaller quant |
| Aider ignores the rules | confirm the files in `read:` exist and paths are correct (run from the project root) |

## How this maps to the setup

- **Driver:** Aider (rule-only adapter — commands become EXECUTE-NOW procedures in `CONVENTIONS.md`).
- **Model:** your local GGUF via `llama-server` (free).
- **Setup:** rules + `ai/` knowledge loaded via `read:`; heavy Claude-only multi-agent commands degrade to single-pass here.
- Reference: `templates/tool-adapters/aider/adapter.md` (Aider translation) · `ai/references/models.md` (driver→model routing).
