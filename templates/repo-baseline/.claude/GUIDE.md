# .claude/ Guide

Single-page catalog of everything in this repo's `.claude/`.

## Scenarios → tool

| You want to... | Use |
|---|---|
| Run lint/type-check after editing | Automatic via `hooks/post-edit-check.sh` |
| Block writes to sensitive files | Automatic via `hooks/pre-edit-guard.sh` |
| Get a briefing at session start | Automatic via `hooks/session-start.sh` |

## Agents

- `verifier.md` — the independent judge. Fresh context, read-only (Read, Grep, Glob, Bash held to tests / scanners / localhost probes by `judge-bash-guard.sh`). Mode `acceptance` grades a run's locked `ai/runs/<run>/acceptance.json` against tests it runs at HEAD; mode `refute` runs `templates/snippets/refute-before-report.md` over review candidates. It is dispatched with a delegation brief — paths and a mode, never the builder's narrative — and ends with one JSON object that `persist-verdict.sh` validates and stamps into `verdict.json`. `knowledge-curator.md` — maintains `ai/` over time.

## Commands

- `fix-bug.md` — universal reproduce → failing-test → fix → verify workflow. `--plan` handoff; `--fast` emergency-hotfix mode.
- `execute-plan.md` — implement a saved `--plan` file; auto-invokes `/verify-plan`.
- `verify-plan.md` — audit an implementation against its plan; halts on drift.
- `ship.md` — package the working tree into a reviewed PR (stage → commit → push → PR), confirm-gated, never-stage guard, `--cleanup` for stale branches.
- `catchup.md` — reseat context after `/clear`: reconstruct branch state (read mode) or write the `.claude/HANDOFF.md` note (`handoff` mode).

## Rules

See `.claude/rules/` (and `.claude/rules/README.md` for the two-tier model). Claude Code loads every rule in `.claude/rules/` without `paths:` frontmatter at launch, every session; the project `CLAUDE.md` `@`-imports list the always-on set for review. **Path-scoped rules** (those with `paths:` frontmatter, e.g. `migration-safety.md`) load when Claude reads a matching file, and `inject-path-rules.sh` adds them before an edit of one, so they cost nothing until you work on a file they govern. The always-loaded budget is CI-guarded by `scripts/check-rule-budget.sh`.

## Hooks

- `post-edit-check.sh` — PostToolUse on Edit/Write/MultiEdit. Lints the edited file.
- `format-on-save.sh` — PostToolUse on Edit/Write/MultiEdit. Auto-formats via the project's formatter.
- `auto-test.sh` — PostToolUse on Edit/Write/MultiEdit. Runs the matching test file; silent on success. **Opt-in:** `touch .claude/.auto-test`.
- `pre-edit-guard.sh` — PreToolUse on Edit/Write/MultiEdit. Blocks `.env`, secrets/keys/certs, generated + minified output, lock files, build output, binaries, and edits to hook scripts themselves.
- `secret-scan.sh` — PreToolUse on Edit/Write/MultiEdit. Blocks writes that introduce high-confidence credentials (API keys, tokens, private keys, connection strings).
- `inject-path-rules.sh` — PreToolUse on Edit/Write/MultiEdit. **Context-only** (never blocks): injects a `paths:`-scoped rule from `.claude/rules/` when you edit a file it governs, once per session. See `.claude/rules/README.md`. Opt out: `.no-path-rules`.
- `guard-destructive.sh` — PreToolUse on Bash. Blocks push-to-protected-branch, force-push (allows `--force-with-lease`), `rm -rf` on `/`/`~`/`$VAR`, `DROP`/`DELETE`-without-`WHERE`/`TRUNCATE`, `curl|sh`, `dd`/`mkfs`, `chmod 777`, accidental `publish`. Configurable via `CLAUDE_PROTECTED_BRANCHES`.
- `guard-irreversible.sh` — PreToolUse on Bash, the H3 gate. Before an irreversible REMOTE step — `terraform`/`tofu` apply or destroy, `kubectl`/`helm`/`argocd`/`flux` mutations against any context, cloud CLI create/delete/update (`aws`, `gcloud`, `az`, `doctl`, `flyctl`, `vercel --prod`, …), registry pushes, a migration or drop against a non-local database, a release-tag push — it returns `ask`, so a human approves (auto mode shows the prompt too). With prompts off (`bypassPermissions`/`dontAsk`), inside a subagent, or with `REFRACT_IRREVERSIBLE=deny`, it denies. Plan / diff / `--dry-run` / read-only / local forms pass. guard-destructive keeps local and git-history destruction; no command is guarded twice. **Opt out:** `touch .claude/.no-guard-irreversible`.
- `test-lane.sh` — PreToolUse on Bash. Heavy test runs take turns, one per machine, so parallel agents cannot exhaust its memory; light runs stay parallel. Blocks a full-suite or e2e command (`npm test`, `pytest`, `go test ./...`, `playwright test`, …) that is not going through the lane and prints the exact re-run line: `.claude/hooks/test-lane.sh run '<command>'`, which waits for a free slot, runs, and exits with the command's status. Not gated: one named test file, a type-check, a lint. A green full-suite run records the exact tree it passed on, so `verify-gate.sh` accepts it instead of running the suite a second time. Lane: `/tmp/claude-<uid>/test-lane` (`CLAUDE_TEST_LANE_DIR`); **Tune:** `CLAUDE_TEST_LANE_SLOTS=<n>` on a machine with RAM for more than one suite. **Opt out:** `touch .claude/.no-test-lane`.
- `build-graph.py` (global, `~/.claude/scripts/`) — **not a hook, you call it.** Assembles this project's import graph from `rank-source-files.py` and answers traversal questions the `ai/` tree cannot: `--who-breaks <path>` (every file that reaches it, capped at `--limit`, with the per-hop shape stated first), `--neighbors`, `--path A B`, `--central`. Derived cache at `.claude/_graph.json` (gitignored), fingerprinted on every source file's size+mtime **and on the resolver's own**, so both an edit and a framework upgrade rebuild it. Setup builds it for you (`run-preflight.sh` step 5/5). TS/JS, Vue/Svelte (`<script>` block only), Python and Dart (`package:<self>/` via pubspec `name`); `tsconfig`/`jsconfig` `paths` aliases resolved. An empty answer means no edge RESOLVED, never "safe to change" — and under a file-based router (Nuxt/Next/SvelteKit/Remix) a page or route file having no importers is CORRECT, because the framework reaches it by path; `--stats` discloses that when it applies.
- `risk-tier.py` / `ears-lint.py` / `trace-matrix.py` (`.claude/scripts/`) — **not hooks; the delivery run calls them.** `risk-tier.py` computes a change's tier (T0–T3, `.claude/templates/governance/tiers.json`) from the request text, the predicted or actual file set through `ai/risk-map.json`, and caller counts in `.claude/_graph.json`; with `--run=<id> --write` it only ever promotes and records why and which phases to back-fill; `--ci` exits 3 on an under-tiered run. `ears-lint.py` holds `requirements.md` to EARS (every story with an IF-THEN failure clause, no vague response words). `trace-matrix.py <run> --phase=analysis|plan|build` fails on any orphan between REQ → AC → task → test. Each prints `--help`-style usage with no arguments.
- `ci-graph.py` (`.claude/scripts/`) — **not a hook; the CI detectors call it** (devops `pipeline-integrity-scan` / `deploy-safety-scan`, security `ci-security-scan`, testing `suite-execution-scan`, `/devops-fix`). Parses `.github/workflows/*` with a real YAML loader (PyYAML, else ruby, else `uv run --with pyyaml`; none → exit 2 `NOT-RUN`) and prints cross-job facts a grep cannot decide: `--check=pin-priv,deploy-concurrency,deploy-gate,timeout,matrix,cache-keys` (or `--all`), `--required` (the branch's required checks joined to jobs; needs `gh`), `--deploy-ancestors`, `--job-of` / `--shell-of <file:line>`, and `--diff-guard=<ref>` (with `--allow-job=FILE:JOB` / `--allow-workflow=FILE:KEY`) (a fix may change `on:`/`if:`/`needs:`/`concurrency:`/`permissions:`/`environment:` only in its own job). Rows are `file:line: CODE key=value`; exit 0 clean · 1 findings · 2 NOT-RUN. `--self-test` proves it.
- `inject-blast-radius.sh` — PreToolUse (Edit|Write|MultiEdit). **Context-only, never blocks.** When an edit touches a file that at least 5 files import DIRECTLY, injects the dependent count, the per-hop shape and the direct importers, read from `.claude/_graph.json`. Once per file per session. The threshold is on direct importers because transitive reach covers ~90% of files in a monorepo and would fire on every edit. The graph is deliberately allowed to be stale — it goes stale on the first edit of a session — so the injected text says so and points at `build-graph.py --who-breaks` for a fresh answer. **Opt out:** `touch .claude/.no-blast-radius`. **Tune:** `BR_MIN=<n>`.
- `recall-inject.sh` — UserPromptSubmit. **Context-only** (never blocks): BM25-searches this project's existing `ai/` memory with your prompt and injects the top 3 matching POINTERS (`path:line`), once per row per session. Stores nothing and adds no sink — the index is a derived cache at `.claude/_memory-index.json` (gitignored). **Opt-in:** `touch .claude/.recall`. See `/recall` for the manual query.
- `session-start.sh` — SessionStart. Prints branch, uncommitted count, last 5 commits, `ai/status.md` Recent Changes, learning queue; after a compaction (source `compact`), the run's handoff.
- `notify.sh` — Notification. Native OS notification (macOS/Linux/WSL) when Claude needs attention.
- `baseline-capture.sh` / `behavior-diff.py` / `perf-compare.py` (`.claude/scripts/`) — **not hooks; the characterize skill, `/add-feature` P5, `/refactor`, `/optimize`, `/upgrade-dep` and `/migrate` call them.** `baseline-capture.sh register` adds an entry (kind, engine, command, scope, artifact, tolerance) to the committed registry `.claude/baselines/main/manifest.json` (`templates/schemas/refract/baseline-manifest.schema.json`); `capture` records behaviour BEFORE an edit into `.claude/baselines/<sha>/` (git-ignored) — 3 identical runs, a differing entry is quarantined with an owner and an expiry — and never rewrites a stored expectation without `--rebaseline`. `behavior-diff.py` is G14/G4's engine (golden-master compare with the `parity-test-generate` tolerance taxonomy; the base side re-captured in a worktree at the merge-base when the stored one is from another sha). `perf-compare.py` refuses a verdict on fewer than `THR-PERF-REGRESSION` runs, on non-interleaved samples or on noise wider than the threshold; `--self-test` shows its false-block rate. An intended difference is declared on the criterion that wants it: `"changes_baseline": ["<entry>/<case>"]` in `acceptance.json`; a rewrite of a stored snapshot without one is a `test-integrity.py` finding. CI: `refract-baselines-main` (merge: cheap kinds; nightly: visual, accessibility, performance HEAD-vs-HEAD as noise calibration).
- `verify-gate.sh` / `update-session-log.sh` — Stop hooks (verify gate + session-log append). When the session left uncommitted source changes, the gate runs `.claude/scripts/gate-check.py --local`: G0 every run contract in the change is locked and intact (`lock-acceptance.sh`), G1 the project's tests (through `test-lane.sh` when it ships, skipped when the agent's own green run already covered this exact tree) and the verifier's `verdict.json` (present, signed by a judge, fresh — a code change after the verdict makes it STALE — and PASS), G2 test integrity (`test-integrity.py` — deleted tests, fewer assertions, new skips, lowered coverage floors, removed CI test steps, a snapshot or baseline re-recorded with no criterion declaring it) and test oracles (`oracle-check.py` — cases that assert nothing that could fail), G3 secrets, G7 lint / typecheck / standards (`standards-check.py`) and persisted reviews, G14 the behavioural baseline (`behavior-diff.py`: every baseline entry whose scope the change touched, re-run at HEAD — a difference no acceptance criterion declares FAILs; shadow), G4 performance in CI only (`perf-compare.py`, interleaved base/head; shadow), G15 the provenance trailer and the signer ≠ author check on every judge record. Each check's mode — `shadow` · `warn` · `block` — is set in `.claude/gates.json`; only a `block` FAIL stops the session. Each result is a record in `.claude/evidence/<sha>/` (git-ignored). No test runner is reported **UNVERIFIED**, never passed in silence. The same script runs in CI as the `refract-gates` job, in shadow mode. **Opt out:** `touch .claude/.no-verify-gate`. The session-log entry also records the harness's own `session_id` + `transcript_path` as POINTERS — the transcript itself is never copied into the repo. The first prompt (≤120 chars) is recorded only under the `.recall` opt-in.

- `test-lock.sh` — PreToolUse on Edit/Write/MultiEdit and Bash. A run's acceptance contract and the tests it names are locked (`.claude/scripts/lock-acceptance.sh <run>` → `.claude/locks/<run>.json`) before production code is written; from then on an edit to them is denied unless a human reopened the lock (`lock-acceptance.sh --reopen <run> --reason=…`, which this hook turns into a permission prompt) for the editing agent (`agent_type` from the hook input; default `test-engineer`). A builder that finds a criterion wrong reports `SPEC_CONFLICT`. It also keeps hook-written records (locks, evidence, verdicts, reviews, the review-dismissals sink) out of tool reach, asks before a human dismissal (`review-dismissals.py dismiss`), and logs who edited what to `.claude/evidence/edits.jsonl`. **Opt out:** `touch .claude/.no-test-lock`.
- `judge-bash-guard.sh` — PreToolUse on Bash, Read/Grep/Glob and Agent/Task, for judges only (`REFRACT_JUDGE_AGENTS`, default `verifier`): tests, scanners, read-only shell and git, localhost probes, scratch files under `/tmp`; no repository or git write, no commit messages, no ledger. On a dispatch TO a judge it lints the brief: run_id + mode + paths, never "I implemented… all tests pass… safe to merge". **Opt out:** `touch .claude/.no-judge-guard`.
- `artifact-ownership.sh` — PreToolUse on Edit/Write/MultiEdit, right after `test-lock.sh`. One writer per run artifact (`.claude/templates/snippets/run-ledger.md` § 2), keyed on `agent_type` from the hook input: a known role (product-analyst, architect, test-engineer, ux-designer, doc-writer, platform-engineer) writes only its own paths; a judge (verifier, plan-critic, `*-reviewer`, `*-auditor`) writes nothing; any other agent may not write a run's role- or orchestrator-owned files or holdouts; while an open run is T2/T3 the main session dispatches the owner instead of writing `requirements.md` / `design.md` / `acceptance.json` …, and in P6 dispatches `@implementer` instead of editing source. Also on Read/Grep/Glob: a subagent other than `test-engineer` and `verifier` may not read `.claude/holdouts/`. Engine `.claude/scripts/ownership-guard.py` (`who <path> --agent=<role>` dry-runs a write; project override `.claude/artifact-ownership.json`). No python3 → allowed with a note. **Opt out:** `touch .claude/.no-artifact-ownership`.
- `precompact-handoff.sh` — PreCompact. Writes `ai/runs/<run>/handoff.json` for each open run (intent, tier, phase, phase states, loop counters, files changed, the ledger's Open and Plan lines, the next phase; `.claude/evidence/handoff.json` when no run is open) and prints a short "preserve" brief, which Claude Code passes to the summariser as custom instructions. Always exits 0 — exit 2 would block the compaction. `session-start.sh` prints the handoff back when the session resumes with source `compact`. **Opt out:** `touch .claude/.no-precompact-handoff`.
- `persist-verdict.sh` / `persist-review.sh` — SubagentStop. The verifier's and a review lens's final JSON is validated against `.claude/schemas/` and the posting bar, stamped with the signer (from the hook input), the authors (edit log) and the scope (blob of every touched path), and written to `ai/runs/<run>/verdict.json` / `reviews/<agent>-<lens>.json`. Malformed output, a kept finding without proof, or a PASS the evidence does not support goes back to the agent (exit 2). A refute-mode verdict also appends each **refuted** candidate to `ai/dynamic/review-dismissals.jsonl` (append-only, hook-owned; the calibration sink of spec § 5.8). `review-dismissals.py` (`.claude/scripts/`, not a hook) records a human `dismiss … --reason=accepted-risk|false-positive --by= --note=` (test-lock asks you first) and `propose --write` regenerates `ai/dynamic/calibration-proposals.md`: precedent candidates (one class dismissed ≥3× for the same reason over ≥2 runs) and demotion candidates (a detector § whose refuted + false-positive rate is above 10 % over ≥20 raised). Proposals only — you confirm them in `/learn-from-task`'s confirm-list. `--self-test` proves it.

Opt-in flags (create the file in `.claude/`): `.auto-test`, `.recall`. Opt-out flags: `.no-guard-destructive`, `.no-guard-irreversible`, `.no-test-lane`, `.no-pre-edit-guard`, `.no-secret-scan`, `.no-format`, `.no-path-rules`, `.no-verify-gate`, `.no-test-lock`, `.no-judge-guard`, `.no-artifact-ownership`, `.no-precompact-handoff`. Fixture tests: `bash tests/hooks/run.sh` (in the config repo).
