# Backend — essentials manifest

Files listed above are the minimal subset copied when `/setup-project --minimal` is used. Standard mode copies the entire pack; minimal mode copies only essentials.

Rationale per category (one line each):
- agents: api-architect designs (proposer), api-reviewer checks output (the judge `/backend-audit` and `/backend-fix` hand every detector row to), bug-investigator covers the most common backend task (debugging) — the minimum trio for design+review+fix.
- commands: add-feature/add-endpoint cover the two main creation flows; fix-bug covers the most frequent maintenance task. **`backend-audit` and `backend-fix` ship as a pair** — the audit's report is the fix loop's input, and the fix loop re-runs the detector that found each row.
- skills: endpoint-test-method verifies a controller/DTO works end-to-end — essential after every backend change. **`validation-boundary-scan` (with `scripts/dto-types.py`), `edge-error-scan` and `http-contract-scan`** are the three detectors whose classes every API has — a body the pipe never sees, an error answered 500, a wrong status — and the ones `/add-endpoint`'s gate runs (VB §1/§2/§3/§5/§7, EE §1/§2/§6, HC §1/§2/§3/§5); `http-contract-scan` also reads dto-types' HANDLER rows, which is why it travels with `validation-boundary-scan`. `wire-format-scan`, `job-lifecycle-scan` and `state-transition-scan` stay in standard mode: in a minimal install `/backend-audit` prints their rows `not run (detector absent)` and its verdict stays unverified, never clean. parallelize-independent-ops covers the highest-leverage performance refactor (sequential-await → bounded parallel) which LLMs miss by default.
- rules: backend-principles (layering / safety) AND concurrency-discipline (no sequential `await` of independent I/O). Concurrency is non-essential ONLY for synchronous-by-language stacks; on Node.js / Python-async / Go / Java / .NET it's load-bearing.
- ai-patterns: api-contract (request/response shape), error-handling (must-have safety pattern), request-validation (load-bearing inbound safety — boundary validation + writable-field allow-list stops mass-assignment / over-posting and unbounded input; the backend-principles Hard rule (a) floor; minimal mode ships it), parallel-io (cites the project's actual concurrency primitive — without it, agents reach for generic `Promise.all` and miss bounding / cancellation / batch APIs), rate-limiting (load-bearing inbound safety — every public/expensive endpoint needs an enforced 429 limit; minimal mode ships it). conditional-requests (ETag/optimistic-concurrency) and pagination (cursor-first, default+max limit, stable sort — a MUST on every list endpoint) ship in standard mode; response-streaming, async-job-offload, webhook-flow (inbound signature-verify + replay + enqueue-then-ack; outbound signing + retry/DLQ), transaction-boundary (intra-service write-set atomicity + optimistic/pessimistic locking), file-upload (magic-byte validation / size cap / presigned direct-to-storage / uuid keys) and agent-callable-api (description-as-interface, closed input schemas, self-correcting errors, response-size budget, server-side destructive gates, token audience/scoping) are signal-gated (large-result / background-job / webhook / transaction / upload endpoints; an MCP or tool-calling surface for the last) and ship in standard mode. agent-callable-api stays OUT of minimal deliberately — minimal already carries five patterns, and a project with no autonomous caller pays its whole cost for nothing. Migration safety (the online-safe / reversible verifier) is the database pack's `migration-safety` skill, not a backend artifact: when the database pack is installed, `add-endpoint` / `add-module` migrations get it through `/migration-review`; without it, the floor is `rules/migration-backend.md`. multi-tenancy is a signal-gated pattern (fires on a multi-tenant signal) — also mirrored under `templates/domains/multi-tenant/`; neither is in the minimal essentials.
