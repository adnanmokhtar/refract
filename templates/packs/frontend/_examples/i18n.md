# Pattern: i18n

> **Hard rule:** A key names a **concept**, not a string of copy, and every plural passes through ICU rather than a ternary. Concatenating translated fragments to build a sentence, and formatting a date / number / currency without an explicit locale, are forbidden. Every finding cites the key or the call site at `<path:line>`.

**Scope.** `.claude/rules/i18n.md` owns **how many locales the code assumes** (dynamic-key types, the ternary-reducer ban, the empty-translations factory, RTL logical properties). `@i18n-auditor` owns detection — parity, unused and undefined keys, hardcoded strings. `/i18n-audit` owns the extractor pass. This pattern owns the four things none of them carry: **key architecture, ICU plurals, `Intl` formatting, namespace loading.** A section here that restates the rule or the auditor is a defect in this file.

**Halt conditions / mandatory cites**
- A new key MUST cite the namespace file it lands in at `<path:line>`.
- Any plural MUST cite the ICU message, not the call site.
- Date / number / currency formatting MUST cite the locale-aware formatter, never a raw `toString` / template literal.
- If the project's i18n library and locale layout are not extracted, halt before adding strings.

## Key architecture

**Namespace by feature, not by page.** A `products` namespace is reused across list / detail / edit; a `page-1` namespace dies the moment a page is renamed. The dot-path (`products.form.price_label`) is the only identifier components reference: moving files inside the locale directory is safe, **renaming a key is a contract change**.

**Name the key for the concept, never for the copy.**

```
BAD:   products.form.create_product_button       // named after what it says today
GOOD:  products.form.submit_create               // named after what it does
```

When the copy changes to "Add item", the BAD key still says `create_product_button` in every locale file and in the translation platform — translators read a key that contradicts its value, and someone renames it. A copy edit should not cause a contract change.

**Scope follows reuse.** Module keys in the module's locale files; genuinely cross-module strings (common buttons, route titles) in the shared file.

## Plurals — ICU, and the category people get wrong

```ts
// WRONG — a ternary handles exactly one language
const text = `${count} ${count === 1 ? 'order' : 'orders'}`;

// RIGHT — ICU in the locale file; the locale applies its own rules
// en.json: "{count, plural, =0 {No orders} one {# order} other {# orders}}"
// ar.json: "{count, plural, =0 {…} one {…} two {…} few {# …} many {# …} other {# …}}"
const text = t('orders.count', { count: 5 });
```

Arabic distinguishes one, two, few, many and other; Russian has separate forms for 1, 2-4 and 5+; English has one and other.

**`=0` and `zero` are not the same thing.** `=0` is an exact-value match and works everywhere. `zero` is a CLDR plural *category*, selected only by locales whose rules define it — English does not. A `zero {No orders}` branch in `en.json` is dead code: English resolves to `other` and renders "0 orders". Use `=0` for empty-state copy.

**Never assemble a sentence from parts.** One key, one whole sentence, interpolation inside the message — word order belongs to the translator, and it is only theirs if the whole sentence is.

## `Intl` — locale and currency are independent axes

```ts
// WRONG
const formatted = `$${price.toFixed(2)}`;
const date = new Date().toLocaleDateString();

// RIGHT — explicit locale; currency is a separate argument
new Intl.NumberFormat(locale, { style: 'currency', currency }).format(4250);
```

**Currency is a property of the transaction, not of the reader** — `locale` decides digits and symbol placement, `currency` decides which money it is. Deriving one from the other re-denominates prices.

**Always pass an explicit `timeZone` to `Intl.DateTimeFormat`.** Omitted, it uses the runtime's zone: the container's on the server, the user's in the browser — two strings for the same instant, i.e. a hydration mismatch (`ssr-safety.md` detector 5 finds it).

## Namespace loading

Load the active locale only, split per namespace. **The cost usually missed:** a namespace that has not arrived renders the raw key or falls back to the pivot locale for a frame. Await the namespace load in the same boundary that awaits the route's data; a locale switch has the same shape.

## Cross-frontend key consistency

Several frontends in one workspace use the **same key** for the same concept. Diverging keys double translation cost and drift — the two get edited separately and the product says two different things for one number.

## Detectors (cite-or-halt)

1. **Ternary plural** — `count === 1 ? 'order' : 'orders'`, or a `${n > 1 ? 's' : ''}` suffix. `report-with-fix`.
2. **Dead `zero` category** — a `zero {` branch in a locale whose rules never select it. `report-with-fix`; replace with `=0`.
3. **Concatenated translation** — `t('a') + ' ' + t('b')`, or a translated fragment joined to a variable. `report-with-fix`.
4. **Copy-named key** — a key leaf that repeats its own English value. `[self-policed]`; reports for a human, never auto-renames.
5. **Formatting with no explicit locale** — `toLocaleDateString()` / `Intl.NumberFormat()` with an empty argument list. `report-with-fix`.
6. **`Intl.DateTimeFormat` with a locale but no `timeZone`** — `report-with-fix` on SSR routes; `dismiss` on a CSR-only app (one runtime, one zone).
7. **Currency derived from locale** — `locale === 'de-DE' ? 'EUR' : 'USD'`. `report-with-fix`.
8. **Namespace rendered before it loads** — a lazily-registered namespace with no awaited boundary above its consumers. `report-flagged`.

## Closure verbs

Exactly one verb per finding. Emits `report-with-fix`, `report-flagged`, `dismiss`, `halt-handoff` (locale count and RTL → `.claude/rules/i18n.md`; parity / unused / hardcoded → `@i18n-auditor` and `/i18n-audit`; hydration → `ssr-safety.md`), `halt-missing-cite`.
