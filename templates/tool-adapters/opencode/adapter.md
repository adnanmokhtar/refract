# OpenCode adapter

**Tool:** SST's OpenCode (open-source Claude Code alternative).
**Docs:** https://opencode.ai/docs/config/ · https://opencode.ai/docs/agents/ · https://opencode.ai/docs/commands/ · https://opencode.ai/docs/skills/
**Capabilities:** R, A (native folder), S (native folder), C (native folder), no hooks.

> **OpenCode standalone goal**: a project generated by `/setup-project` with the `opencode` adapter selected MUST work end-to-end in OpenCode with **no `.claude/` present**. Agents, commands, and skills land in OpenCode's native `.opencode/{agents,commands,skills}/` folders so they appear in OpenCode's pickers exactly the way Claude Code surfaces them.

## Target files

```
repo-root/
├── AGENTS.md                                  # Cross-tool rules file (also read by OpenCode)
├── opencode.json                              # Provider config + instructions globs (+ optional commands fallback block)
└── .opencode/                                 # NATIVE — OpenCode reads this directory tree
    ├── agents/
    │   └── <agent-name>.md                    # NATIVE — one file per agent persona
    ├── commands/
    │   └── <command-name>.md                  # NATIVE — one file per slash command
    └── skills/
        └── <skill-name>/
            ├── SKILL.md                       # Skill body + frontmatter
            └── *.sh / *.py                    # Optional supporting scripts (copied verbatim)
```

OpenCode also continues to globally read `~/.config/opencode/` (user-level) — repo-local `.opencode/` overrides global.

> **Migration note**: pre-Apr-2026 setup-project crammed every command into the `opencode.json` `commands` block and relied on OpenCode globally reading `~/.claude/skills/`. The new layout uses repo-local native folders so the project is self-contained — no symlink trick required for OpenCode to see the project's skills.

## File formats

### `AGENTS.md` (shared with other AGENTS.md consumers)
Plain markdown. Same file that Codex, Cursor, Amp, Cline, Copilot, and Windsurf read. Treat as the single canonical instructions source.

### `opencode.json`
JSON. Schema (per OpenCode's published config schema as of Apr 2026 — only these top-level keys are accepted):
```json
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "anthropic": { "api_key": "..." },
    "openai":    { "api_key": "..." },
    "moonshot":  { "api_key": "...", "base_url": "https://api.moonshot.ai/anthropic" }
  },
  "model": "anthropic/claude-sonnet-4-6",
  "instructions": ["AGENTS.md", "CLAUDE.md", ".claude/rules/*.md", "ai/patterns/*.md"]
}
```

> **DO NOT** write `_generator`, `_generator_fields`, `_version`, `_generated_at`, `_note`, or `commands` keys at the top level. OpenCode's schema rejects unrecognized keys with `Configuration is invalid` and the binary refuses to start. Commands ship under `.opencode/commands/<name>.md` (see "Full artifact translation" below), not inside `opencode.json`.

The `instructions` array is an **extension point** — any markdown listed here is loaded as context. This lets OpenCode reuse our `.claude/rules/*.md` verbatim.

## Translation recipe

1. If `AGENTS.md` doesn't exist → write it (source: Claude Code adapter's `CLAUDE.md` compacted).
2. If `opencode.json` doesn't exist → write it with ONLY schema-valid keys:
   - `$schema` → `"https://opencode.ai/config.json"`.
   - `provider` block (defaults: anthropic; user fills API keys).
   - `instructions` glob pointing at `AGENTS.md` + `.claude/rules/*.md` + `ai/patterns/*.md` + `ai/references/*.md`.
   - No model pinning unless user specifies (lets OpenCode pick based on provider availability).
   - **No metadata keys, no inline commands block.**
3. Commands from `.claude/commands/*.md` → write to `.opencode/commands/<name>.md` (the NATIVE folder; see "Full artifact translation" below). Do NOT embed in `opencode.json`.
4. Validate before write: the file MUST parse as JSON AND have only keys from the allowed top-level set (`$schema, provider, model, instructions`). Any other key → drop and surface a warning.

## Idempotency

`opencode.json` is regenerated by re-scanning the `instructions` list. The `provider` block is preserved bit-identically (the user owns those keys for their API credentials).

Tracking metadata (generator name + version + timestamp) lives in a SIDECAR file, NOT inside `opencode.json`:

```
.opencode/_setup-project-meta.json
```

Schema (sidecar — not constrained by OpenCode):
```json
{
  "_generator": "claude-setup-project",
  "_version": "<setup-project version>",
  "_generated_at": "<ISO timestamp>",
  "_generator_fields_in_opencode_json": ["instructions"]
}
```

The sidecar is the single source of truth for "what setup-project owns" and "what the user added." Re-runs read the sidecar to preserve user-added keys and overwrite generator-owned ones.

## Known gotchas

- OpenCode does NOT have its own agents directory. "Agents" in OpenCode means the same AGENTS.md — there's no specialized-persona dispatch.
- OpenCode is reported to read `~/.claude/skills/` globally (not per-project) — verify against current OpenCode docs at https://opencode.ai/docs/rules/ before relying on it. Skills in this repo's `.claude/skills/` are NOT auto-available to OpenCode unless the user globally installs them (or symlinks).
- No hooks. Pre-edit validation / post-edit checks are not expressible in OpenCode.
- Config can live in `~/.config/opencode/opencode.json` globally; per-project `opencode.json` overrides globals.

## Full artifact translation

### Commands — `.claude/commands/<name>.md` → `.opencode/commands/<name>.md` (NATIVE)

OpenCode reads `.opencode/commands/<name>.md` natively. The adapter copies each Claude command to its native location 1:1:

```markdown
---
description: Hit a dev endpoint via curl and verify DTO shape
agent: build
model: anthropic/claude-sonnet-4-6
---

# /endpoint-test

<body of .claude/commands/endpoint-test.md>

Arguments: $ARGUMENTS
```

User invokes: `/endpoint-test <controller>` in OpenCode chat.

Path: `.opencode/commands/<name>.md` (no prefix — filename = slash-command name).

> **Backward-compat fallback**: the same command can ALSO be mirrored into `opencode.json` `commands.<name> = {description, template}` for older OpenCode builds that pre-date `.opencode/commands/`. Mirror only on `--legacy-opencode` flag; not the default.

### Agents — `.claude/agents/<name>.md` → `.opencode/agents/<name>.md` (NATIVE)

OpenCode now reads `.opencode/agents/<name>.md` as a first-class persona definition:

```markdown
---
name: backend-reviewer
description: Reviews backend code for repository / service / controller hygiene
mode: subagent
model: anthropic/claude-sonnet-4-6
tools:
  read: true
  edit: false
  bash: false
---

<agent body from .claude/agents/backend-reviewer.md>
```

OpenCode picks this up the same way Claude Code picks up `.claude/agents/<name>.md`. Manual invocation in chat: `@backend-reviewer review this PR diff` (OpenCode's persona-mention syntax).

`AGENTS.md` still gets a `## Named personas` section as documentation for users who don't know the `@` syntax — but the actual persona behavior is driven by `.opencode/agents/<name>.md`.

### Skills — `.claude/skills/<name>/` → `.opencode/skills/<name>/` (NATIVE folder copy)

OpenCode reads `.opencode/skills/<name>/SKILL.md` per-project natively (same shape as Claude). The adapter copies the entire skill folder verbatim:

```
.opencode/skills/module-scaffold/
├── SKILL.md            # Frontmatter + body, copied 1:1 from .claude/skills/module-scaffold/SKILL.md
├── scaffold.sh         # Copied verbatim
└── templates/          # Sub-resources copied verbatim
```

`SKILL.md` frontmatter:

```markdown
---
name: module-scaffold
description: Scaffold a new NestJS module matching project conventions
---

<skill body>
```

OpenCode surfaces this in its skills picker. Supporting scripts run via OpenCode's bash tool. **No symlink to `~/.claude/skills/` required** — the project is self-contained.

### Hooks — `.claude/hooks/*.sh` → git hooks + AGENTS.md disclosure

OpenCode has no lifecycle hooks. Fallbacks:

1. **Pre-commit / post-commit coverage** → install `.husky/` (or vanilla `.git/hooks/`) replicating `post-edit-check.sh` + `pre-edit-guard.sh`:
   ```bash
   # .husky/pre-commit
   pnpm lint-staged
   grep -rn 'console\.log' --include='*.ts' src/ && exit 1 || true
   ```
2. **Session-start / session-stop gaps** → document in `AGENTS.md`:
   ```markdown
   ## Before starting a session
   Read `ai/status.md` for current phase + in-flight work.

   ## Before committing
   Ensure `pnpm lint` + `pnpm test` pass. `ai/dynamic/session-log.md` — manually append an entry if work spans sessions.
   ```
3. **Flag in `ai/references/tool-parity.md`** → list which hooks become non-enforced when the user drives with OpenCode.
