# Continue.dev adapter

**Tool:** Continue.dev (IDE extension for VS Code + JetBrains).
**Docs:** https://docs.continue.dev/customize/deep-dives/rules · https://docs.continue.dev/customize/deep-dives/prompts
**Capabilities:** R, C (native — `.continue/prompts/*.md` with `invokable: true` slash commands), partial A (personas as prompts), no hooks.

> **Continue standalone goal**: a project generated by `/setup-project` with the `continue` adapter selected MUST work end-to-end in Continue with **no `.claude/` present**. Rules attach automatically; slash commands appear in chat via the prompts picker; agents and skills fall back to prompts (Continue has no native equivalent).

## Target files

```
repo-root/
├── .continue/
│   ├── config.yaml                          # Main config (JSON is deprecated — always emit YAML)
│   ├── rules/
│   │   ├── project.md                       # Project-wide rules
│   │   ├── <domain>.md                      # Per-domain rules
│   │   └── <stack>.md                       # Per-stack rules
│   └── prompts/                              # NATIVE — slash commands + persona/skill invocations
│       ├── <command-name>.md                # invokable: true → /<command-name> in chat
│       ├── agent-<name>.md                   # Persona invocation (no native dispatch)
│       └── skill-<name>.md                   # Procedure invocation
├── .continueignore                           # Pre-edit guard fallback (.env, *.lock, migrations)
└── AGENTS.md                                 # Continue also reads this if present (via config include)
```

## File formats

### `.continue/config.yaml`
YAML. Minimal schema:
```yaml
name: <project-name>
version: 0.0.1
schema: v1

models:
  - name: Claude Sonnet
    provider: anthropic
    model: claude-sonnet-5
    roles: [chat, edit, apply]
  - name: Kimi K2
    provider: openai
    model: kimi-k2-turbo-preview
    apiBase: https://api.moonshot.ai/v1
    roles: [chat]

rules:
  - uses: .continue/rules/project.md
  - uses: .continue/rules/database.md

docs:
  - name: Project AI Knowledge
    startUrl: file://./ai/README.md

# Optional slash commands (per-repo)
prompts:
  - name: review
    description: Review recent changes
    prompt: |
      Review the staged + working-tree diff against the rules in AGENTS.md + .claude/rules/*.md.
```

### `.continue/rules/*.md`
Markdown with YAML frontmatter:
```yaml
---
name: Rule name (required)
description: Short summary
globs: "src/**/*.ts"        # Optional; applies when file matches
alwaysApply: true           # Optional; default false
---
```
Body = prose rules. Like Cursor's MDC but with `.md` extension and no special `@file` syntax. Continue inlines rules by reading file contents.

## Translation recipe

1. **`.continue/config.yaml`** — write with:
   - `models:` block commented out except Anthropic (user fills API keys or env vars).
   - `rules:` block referencing each generated `.continue/rules/<name>.md`.
   - `docs:` pointing at `ai/README.md`.
2. **`.continue/rules/<name>.md`** — one per `.claude/rules/<name>.md`:
   - Frontmatter: `name`, `description`, optional `globs`, `alwaysApply`.
   - **Authoritative `paths:` (preferred).** If the source rule carries `paths:` frontmatter (a YAML glob list, e.g. `migration-safety.md`), copy those globs **verbatim** into `globs:` and set `alwaysApply: false` — don't re-infer. A rule with no `paths:` is always-apply.
   - Body: copy the rule prose verbatim (Continue doesn't support `@file` inlining — must embed).
3. **`.continue/rules/project.md`** — always-apply rule summarizing CLAUDE.md's top-level conventions.
4. **Do NOT port `inject-path-rules.sh`** — the Claude-only mechanism for applying `paths:` rules; Continue's `globs:` frontmatter is its native equivalent. (Continue has no hooks anyway.)
5. **`inject-blast-radius.sh` IS ported, unlike `inject-path-rules.sh`.** Continue's `globs:` frontmatter replaces static path-scoped rules; it cannot express a dependent count read from `.claude/_graph.json` at edit time. If Continue exposes no per-edit hook, document it in the rules file as a manual step (`build-graph.py --who-breaks <file>` before touching a shared file) rather than dropping it silently.

## Idempotency

`config.yaml` is regenerated; `models:` block preserves user-specified API keys via env-var references (`apiKey: ${{ secrets.ANTHROPIC_API_KEY }}`).

`.continue/rules/*.md` files are fully regenerated (user edits go into separate files, not generator-owned ones). Convention: user adds `.continue/rules/custom-*.md` — generator never touches `custom-*` prefix.

## Known gotchas

- JSON config (`config.json`) is deprecated. Always emit YAML.
- `models:` block requires `roles:` field to distinguish chat vs edit vs autocomplete. Without it, Continue uses the first model for everything.
- Rules do NOT auto-inline referenced files. Copy-paste rule content or use `docs:` for reference context.
- Frontmatter `name:` is required — without it, the rule file is silently ignored.
- Rule file must be inside `.continue/rules/` — nested subfolders are not discovered (as of 2026).

## Full artifact translation

### Commands — `.claude/commands/<name>.md` → `.continue/prompts/<name>.md` (NATIVE, file-per-command)

Continue 1.x reads `.continue/prompts/*.md` natively. Each prompt becomes a slash command when its frontmatter sets `invokable: true`:

```markdown
---
name: endpoint-test
description: Hit dev endpoint via curl and verify DTO shape
invokable: true
---

# /endpoint-test

<body of .claude/commands/endpoint-test.md, with {{input}} placeholder if the command takes args>
```

User invokes: type `/endpoint-test <controller>` in Continue chat.

Path: `.continue/prompts/<command-name>.md` (no prefix — filename is the slash command).

> **Backward-compat fallback**: older Continue versions (<1.0) only read prompts from `config.yaml`'s `prompts:` block. The adapter ALSO emits a minimal `prompts:` mirror in `config.yaml` referencing each `.continue/prompts/<name>.md` via `uses:` so both paths work. Mirror entries are auto-managed by Phase 4.8 / 4.8-DEEP.

### Agents — `.claude/agents/<name>.md` → `.continue/prompts/agent-<name>.md` (translated)

Continue has no native agent dispatch. Personas land in the prompts folder with an `agent-` prefix:

```markdown
---
name: agent-backend-reviewer
description: Review backend code using the backend-reviewer persona
invokable: true
---

# /agent-backend-reviewer

Act as the `backend-reviewer` agent.

**Persona**: <agent body from .claude/agents/backend-reviewer.md>
**Scope**: <from agent frontmatter description>

Apply this persona to the request that follows.
```

Path: `.continue/prompts/agent-<name>.md`.

### Skills — `.claude/skills/<name>/SKILL.md` → `.continue/prompts/skill-<name>.md` (translated)

Continue has no native skills. Procedures land as prompts with a `skill-` prefix:

```markdown
---
name: skill-module-scaffold
description: Scaffold a new NestJS module
invokable: true
---

# /skill-module-scaffold

Follow this scaffolding procedure:

<body of .claude/skills/module-scaffold/SKILL.md>

If shell steps are required, ask the user to run them in a separate terminal — Continue does not execute shell from a prompt.
```

Path: `.continue/prompts/skill-<name>.md`.

### Hooks — `.claude/hooks/*.sh` → `.continueignore` + git hooks + always-apply rules (FALLBACK)

**Native support:** none — as of July 2026 Continue.dev has **no lifecycle-hook mechanism**. `config.yaml`'s top-level keys are `name`, `version`, `schema`, `models`, `context`, `rules`, `prompts`, `docs`, `mcpServers`, `data` — none run a command on a tool/session/prompt event. (Verified against the current config.yaml reference; Continue's extensibility story is rules + MCP servers, not agent-loop hooks.) There is no `preToolUse`/`postToolUse` equivalent, so guards cannot be *enforced* inside Continue — they degrade to advisory rules plus a git backstop.

**Translation of the repo's hooks** — each Claude hook falls back to the nearest non-hook mechanism:

- `guard-destructive.sh` → **git hooks** (Husky `pre-commit` / `pre-push`) — the only enforceable layer; Continue itself will not block a destructive shell command. Also state the prohibition as an always-apply `.continue/rules/` rule so the model is discouraged in-loop.
- `pre-edit-guard.sh` + `secret-scan` → **`.continueignore`** (same syntax as `.gitignore`) keeps sensitive paths out of Continue's context/edit surface — **REQUIRED by the Phase 4.8.0 contract**, not optional:
  ```
  .env*
  *.key
  *.pem
  *.lock
  prisma/migrations/
  database/migrations/
  ```
- `module-boundaries.sh` → **not enforceable in-loop.** `.continueignore` cannot express it (that file hides paths; the rule is about the imports *inside* a file). Restate the declared boundaries as an always-apply `.continue/rules/` rule so the model is discouraged, and back it with a Husky `pre-commit` scan of the staged diff — the shipped script reads the pending edit, so the commit-time port must work from files on disk.
- `post-edit-check.sh` + `format-on-save` + `auto-test.sh` → **IDE-level** (VS Code / JetBrains format-on-save + ESLint-on-save) and Husky `pre-commit` for the test/lint gate.
- `inject-path-rules.sh` → **NOT ported** — Continue's native `globs:` frontmatter in `.continue/rules/*.md` is the path-scoping equivalent (see § Translation recipe).
- `notify.sh` → git `post-commit` hook, or omit (no in-agent notification surface).
- `update-session-log.sh` → **no Stop event** — git `post-commit` hook, or the manual discipline rule ("append a bullet to `ai/dynamic/session-log.md`") in an always-apply `.continue/rules/` file.
- `verify-gate.sh` (Stop) → **not enforceable** — Continue cannot refuse a finish. Husky `pre-commit` / `pre-push` running the test command is the only real gate; state in the rules file that the stop itself is unguarded.

`session-start.sh` (SessionStart) → there is no `sessionStart` hook; put the briefing in `config.yaml` so it loads every session:
```yaml
systemMessage: |
  Read ai/status.md before starting any non-trivial task. Follow the rules in AGENTS.md + .continue/rules/.
```

**Caveats:** none of this is enforced *inside* the agent loop — `.continueignore` limits context but the git hooks are the only hard gate. If Continue ships a hook API later, `guard-destructive` / `pre-edit-guard` / `secret-scan` should move to a native `preToolUse`-equivalent and this section should be promoted from fallback to native.

**Source:** https://docs.continue.dev/reference · https://docs.continue.dev/customize/deep-dives/rules
- `inject-blast-radius.sh` → **no hook mechanism, and no rules fallback either.** Continue's `globs:` frontmatter absorbs `inject-path-rules.sh` because those are static rules; a dependent count read from `.claude/_graph.json` at edit time cannot be written into a rules file. Carry it as an explicit instruction in the always-apply rule: before editing a shared file, run `python3 ~/.claude/scripts/build-graph.py --corpus=project --repo=. --who-breaks <file>`. The check is manual here; say so rather than implying coverage.
