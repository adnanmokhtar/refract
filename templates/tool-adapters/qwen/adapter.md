# Qwen Code adapter

**Tool:** Qwen Code (Alibaba) — terminal CLI agentic coding tool.
**Docs:** https://qwenlm.github.io/qwen-code-docs/en/
**Capabilities:** R (rules via QWEN.md + AGENTS.md), A (native subagents in `.qwen/agents/`), S (native skills in `.qwen/skills/<name>/SKILL.md`), C (native slash commands in `.qwen/commands/`), H (native hooks via `.qwen/settings.json`).

> **Standalone-tool goal**: a project generated by `/setup-project` with the `qwen` adapter selected MUST work end-to-end in Qwen Code with **no `.claude/` present**. Skills land in `.qwen/skills/`; subagents in `.qwen/agents/*.md`; commands in `.qwen/commands/*.md`; hooks in `.qwen/settings.json`; project memory in `QWEN.md` (plus `AGENTS.md` at repo root as the cross-tool canonical).

> **Capability profile.** Qwen Code mirrors Claude Code's primitive set more closely than any other adapter besides OpenCode. The translation is near-1:1 — Markdown-with-frontmatter for commands/agents/skills, JSON settings.json for hooks. Lossless on R/A/S/C/H. `N` (path-scoped rules) has no native rule-glob form, **but is recoverable via hooks**: because Qwen has native hooks, port `inject-path-rules.sh` into the `.qwen/settings.json` hooks block so a rule's `paths:` frontmatter is injected on matching edits — the same mechanism Claude Code uses. **Confirmed (2026-07):** Qwen's `PreToolUse` hooks natively support `hookSpecificOutput.additionalContext`, so this injection works exactly like Claude Code — no `QWEN.md` gap-disclosure fallback needed.

> **Format note (2026-05-14, verified against qwenlm.github.io/qwen-code-docs)**: Qwen Code commands use **Markdown with optional YAML frontmatter** as the current canonical format. The legacy **TOML format is deprecated but still supported** for backwards compatibility — the project recently completed a TOML→Markdown migration of its built-in command set. New projects should generate Markdown commands; if a downstream project has historical `.toml` command files, leave them in place (Qwen still loads them) and add new commands as `.md`. This is the OPPOSITE of Gemini CLI (Qwen's upstream parent), which remains TOML-only — do not assume the two share a format.

## File formats

### `QWEN.md` (project memory)
Plain Markdown. No frontmatter. Loaded automatically when Qwen Code runs in the repo. Filename is configurable via `context.fileName` setting; default is `QWEN.md`.

Loading hierarchy (per Qwen docs):
1. Global: `~/.qwen/QWEN.md`
2. Project root + parent directories up to project root (identified by `.git`) or home directory.

Recommended structure (parallel to AGENTS.md):
- Project overview
- Architecture
- Key commands (build / test / lint)
- Conventions (MUST / MUST NOT)
- Code style
- Testing
- Available subagents (point at `.qwen/agents/`)
- Available skills (point at `.qwen/skills/`)
- Available slash commands (point at `.qwen/commands/`)

### `.qwen/commands/<name>.md` (slash command)
Markdown with optional YAML frontmatter (recommended format; deprecated TOML alternative still parsed).

```markdown
---
description: One-line description shown in /help
---

Prompt body. Use {{args}} for parameters.

Body is procedural Markdown — same content shape as `.claude/commands/<name>.md`.
```

Naming: file path → command name with colons.
- `.qwen/commands/test.md` → `/test`
- `.qwen/commands/migration/phase.md` → `/migration:phase`

Project commands take precedence over global commands when names conflict.

### `.qwen/agents/<name>.md` (subagent)
Markdown with YAML frontmatter (per Qwen subagents docs).

```markdown
---
name: parity-auditor
description: Pre-cutover audit of a per-feature port. Verifies contract / parity tests / artifacts. Halts on missing items.
model: inherit                                # or specific model id, or provider:model
tools:                                         # optional — subset of tools this subagent may use
  - read_file
  - write_file
  - read_many_files
  - run_shell_command
---

You are an audit specialist. <body — system prompt for this subagent>
```

Frontmatter fields:
- `name`: subagent identifier (matches the file's basename for predictability).
- `description`: when + how to use this subagent (read by the main agent for dispatch).
- `model`: optional. `inherit` (default), specific model ID, or `provider:model`.
- `tools`: optional. Whitelist of tools this subagent may invoke. Omit shell/write to make it read-only.

Discovery priority:
1. `.qwen/agents/<name>.md` (project — highest)
2. `~/.qwen/agents/<name>.md` (user)
3. Extension `agents/` directories (lowest)

### `.qwen/skills/<name>/SKILL.md` (skill body)
YAML frontmatter + Markdown body (per Qwen skills docs).

```markdown
---
name: extract-v1-contract
description: Extract a 9-section contract from V1 source as the spec V2 must satisfy. Use when starting any V1→V2 port.
---

# Extract V1 Contract

## Instructions
<step-by-step procedural guidance>

## Examples
<concrete examples>
```

Required: `name` (non-empty string), `description` (non-empty string). Best practice: description names BOTH what the skill does AND when to use it, with keywords users naturally type.

Supporting files (referenced from SKILL.md via standard Markdown links):
- `scripts/` — supporting executables.
- `references/` — read-by-skill reference docs.
- `assets/` — binary assets.

### Hooks — `.claude/hooks/*.sh` → `.qwen/settings.json` `hooks` block

**Native support:** full ✓ — Qwen has a first-class hooks engine merged into `.qwen/settings.json` (project) or `~/.qwen/settings.json` (user); it mirrors Claude Code's model more closely than any other adapter.

**Native mechanism:** JSON `hooks` object keyed by event name, each mapping to an array of `{ matcher, hooks: [ … ] }`. Each hook has `type` (`command` | `http` | `prompt`; `function` is internal-only), `name`, `timeout` (ms, default 60000), plus `async` / `sequential` / `env` / `shell` for command hooks. Command hooks receive JSON on stdin (`session_id`, `transcript_path`, `cwd`, `hook_event_name`, `timestamp` + event-specific fields; subagents also get `agent_id` / `agent_type`) and return JSON on stdout (`continue`, `decision`, `reason`, `hookSpecificOutput.additionalContext`, …). **16 events** (verified 2026-07 against qwenlm.github.io): `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `UserPromptSubmit`, `PermissionRequest`, `SessionStart`, `SessionEnd`, `Stop`, `StopFailure`, `SubagentStart`, `SubagentStop`, `PreCompact`, `PostCompact`, `Notification`, `TodoCreated`, `TodoCompleted`.

**Translation of the repo's hooks:**

| Claude hook | Qwen event | Native? |
|---|---|---|
| `guard-destructive.sh` + `pre-edit-guard.sh` + secret-scan | `PreToolUse` — exit `2` + `decision:"deny"` (or `hookSpecificOutput.permissionDecision:"deny"`) blocks the tool | ✓ native |
| `post-edit-check.sh` + format-on-save + `auto-test.sh` | `PostToolUse` (matcher `Edit\|Write`) | ✓ native |
| `inject-path-rules.sh` | `PreToolUse` returning `hookSpecificOutput.additionalContext` | ✓ native — **CONFIRMED** current: Qwen's PreToolUse supports `additionalContext`, so the `paths:` rule injection works exactly like Claude Code. The adapter's earlier "verify, else degrade to a global `QWEN.md` section" fallback is no longer required. |
| `notify.sh` | `Notification` (or `Stop`) | ✓ native |

```json
{
  "context": {
    "fileName": "QWEN.md"
  },
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "^bash$",
        "sequential": false,
        "hooks": [
          {
            "type": "command",
            "command": "~/.claude/scripts/validate-migration-artifacts.sh --hook-mode",
            "name": "migration-artifact-check",
            "timeout": 30000
          }
        ]
      }
    ],
    "PostToolUse": [],
    "Stop": [],
    "SessionStart": []
  }
}
```

**Caveats:** Blocking requires exit code `2` AND a blocking `decision` (`"block"`/`"deny"`; PreToolUse uses `hookSpecificOutput.permissionDecision:"deny"`). Default `timeout` is 60000 ms (adapter snippets use 30000). `async:true` hooks run in the background and CANNOT return decision control (results arrive via `systemMessage` next turn). `StopFailure` is fire-and-forget (output/exit ignored); `PostCompact` output has no control effect. Todo hooks run in a `validation` (blocking) + `postWrite` (logging) two-phase model. Payload keys are snake_case on stdin but camelCase in the returned JSON (`hookSpecificOutput`, `additionalContext`). Global disable without deletion: `{ "disableAllHooks": true, "hooks": { … } }`.

**Source:** https://qwenlm.github.io/qwen-code-docs/en/users/features/hooks/

## Translation recipe

How `/setup-project`'s artifacts map to Qwen Code's primitives:

| `/setup-project` artifact | Qwen Code destination | Notes |
|---|---|---|
| `.claude/rules/<name>.md` (rules) | `QWEN.md` § `## Rules — <name>` (consolidated) + cross-reference in `AGENTS.md` | Qwen has no separate rules folder; rules become project-memory paragraphs. Procedural rules with workflows MAY also be authored as skills. |
| `.claude/skills/<name>.md` (skills) | `.qwen/skills/<name>/SKILL.md` | Direct 1:1. Frontmatter accepts `name` + `description` (both required, non-empty strings). Supporting files in `scripts/` / `references/` / `assets/`. |
| `.claude/agents/<name>.md` (agents) | `.qwen/agents/<name>.md` | Direct 1:1. Persona body becomes the prompt body; Claude's tool-use config maps to Qwen's `tools:` whitelist. |
| `.claude/commands/<name>.md` (slash commands) | `.qwen/commands/<name>.md` | Direct 1:1. Same frontmatter shape (`description:`). Nested commands use folder structure: `.qwen/commands/migration/phase.md` → `/migration:phase`. |
| `.claude/settings.json` (hooks) | `.qwen/settings.json` `hooks` block | Direct 1:1 on shape. The 12 Qwen events overlap with Claude's PreToolUse/PostToolUse/Stop/SessionStart set. Adapter writes the project-level file. |
| `ai/patterns/*.md` (knowledge) | Read by skills via relative-path links from `SKILL.md` body, OR via cross-references in `QWEN.md` / `AGENTS.md`. | Qwen has no project-knowledge folder; patterns are referenced from skills + memory. |

## Idempotency

- **`QWEN.md`** — managed-block markers `<!-- generated:start -->` / `<!-- generated:end -->` per the universal contract (4.8-DEEP). User-customizable sections preserved verbatim across `--refresh`. First-line generator marker `<!-- managed-by: qwen-adapter -->`.
- **`AGENTS.md`** — Qwen reads it but does NOT own it. Codex owns the file; Qwen contributes via the discipline-enforcement marker block (see `_discipline-enforcement.md`) and the `## Qwen-specific notes` section if any.
- **`.qwen/commands/<name>.md`**, **`.qwen/agents/<name>.md`**, **`.qwen/skills/<name>/SKILL.md`** — managed-block markers in the body (`<!-- generated:start -->` / `<!-- generated:end -->`); user-authored content outside the markers preserved.
- **`.qwen/settings.json`** — JSON merge on `--refresh`. Adapter writes the `hooks.<event>[]` arrays it owns; user-added entries (matched by `name:` field) preserved. The top-level `disableAllHooks` and any non-`hooks` keys are user-owned — adapter reads but never overwrites.

## Known gotchas

1. **No path-scoped rules.** Qwen has no equivalent of Cursor's `globs:` or Cline's per-folder rules. All project rules live in `QWEN.md` plus skills the user invokes contextually.
2. **TOML commands are deprecated, not removed.** Older Qwen Code projects may have `.qwen/commands/<name>.toml`. The adapter writes Markdown-with-frontmatter only; if a `.toml` exists at the same name, the adapter HALTs and asks the user to migrate before re-running.
3. **Subagent dispatch from main agent only.** Subagents cannot create their own subagents. Multi-level dispatch flattens into a single subagent layer in Qwen.
4. **`name` field on skills.** Qwen requires non-empty strings for `name` + `description`. Not as strict as Kimi's `[a-z0-9-]{1,64}` regex, but adapter normalizes to lowercase-hyphenated names for cross-tool consistency.
5. **System-wide settings exist but are out of scope.** The adapter only writes project-level (`.qwen/`) and user-global is left to the user. System-level (`/etc/qwen-code/`) is never touched.
6. **`QWEN.md` and `AGENTS.md` coexist.** Qwen reads `QWEN.md` natively; many Qwen users also read `AGENTS.md`. The adapter writes both — `QWEN.md` is Qwen-specific, `AGENTS.md` is the cross-tool canonical owned by the codex adapter. To avoid duplication, `QWEN.md` can point at `AGENTS.md` for shared content (see "Sample output").
7. **Hooks are JSON inside settings.json, not a separate file.** Unlike Claude Code (`.claude/settings.json` + `.claude/hooks/*.sh`) where hooks are scripts referenced from settings, Qwen merges the hooks block directly into settings.json. Scripts referenced via `command:` field can live anywhere on disk.
8. **Headless invocation.** Qwen Code supports `qwen -p "<prompt>"` (or `--prompt`) for non-interactive use, with `--print` for clean output and `--output-format json` for structured results. This makes Qwen eligible for the parallel-orchestrator scripts (`migrate-parallel.sh`, etc.).
