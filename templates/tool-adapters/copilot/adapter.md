# GitHub Copilot adapter

**Tool:** GitHub Copilot (chat + custom instructions, agent skills, custom agents, chat modes).
**Docs:** https://docs.github.com/en/copilot/reference/customization-cheat-sheet · https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/add-skills
**Capabilities:** R, A (native `.github/agents/`), S (native `.github/skills/`), C (native prompts), **H (native `.github/hooks/*.json` lifecycle hooks — Copilot CLI + Cloud Agent; VS Code Copilot Chat in preview)**, N (path-scoped via `applyTo` frontmatter), chat modes via `.github/chatmodes/`.

> **Copilot standalone goal**: a project generated by `/setup-project` with the `copilot` adapter selected MUST work end-to-end in Copilot with **no `.claude/` present**. Repo-wide instructions, path-scoped instructions, prompts, custom agents, agent skills, and chat modes all land in their native `.github/` subfolders so Copilot Chat (VS Code, JetBrains, github.com) discovers them automatically.

> **Migration note**: pre-Apr-2026 setup-project routed every command/agent/skill into `.github/prompts/*.prompt.md`. Modern Copilot has dedicated folders — agents land in `.github/agents/`, skills in `.github/skills/<name>/SKILL.md`, chat modes in `.github/chatmodes/`. Phase 4.8 / 4.8-DEEP migrate to the native shape on `--refresh`; legacy prompt files remain harmless until cleaned up.

Copilot accepts `AGENTS.md`, `CLAUDE.md`, `GEMINI.md` at root — but the officially documented + supported path is `.github/copilot-instructions.md`. Treat that as primary; AGENTS.md is redundant but harmless (and shared with other tools).

## File formats

### `.github/copilot-instructions.md`
Plain markdown. No frontmatter. Loaded automatically in every Copilot chat session within the repo.

### `.github/instructions/*.instructions.md`
Markdown with YAML frontmatter:
```yaml
---
applyTo: "src/**/*.ts"               # Glob pattern; rule activates when editing matching files
---
```
Body = prose instructions. Only loaded when editing files matching the glob.

## Translation recipe

1. **`.github/copilot-instructions.md`** — compact project overview:
   - Read-before-edit rule.
   - Architecture one-paragraph summary.
   - Top 10 MUST / MUST NOT rules.
   - Pointer to `AGENTS.md` + `ai/README.md` for depth.

   Keep under ~2k tokens — Copilot loads this on every request.

2. **`.github/instructions/<domain>.instructions.md`** — one per major domain:
   - Frontmatter `applyTo:` with appropriate glob.
   - **Authoritative `paths:` (preferred).** If the source `.claude/rules/<name>.md` carries `paths:` frontmatter (a YAML glob list, e.g. `migration-safety.md`), set `applyTo:` from those globs **verbatim** — the rule declared its own scope; don't re-infer. A rule with no `paths:` goes into `copilot-instructions.md` (repo-wide) instead. Note: `inject-path-rules.sh` is NOT ported — `applyTo:` is its Copilot-native equivalent.
   - Body: inline rule content from `.claude/rules/<domain>.md`.
   - Suggested splits (when a rule lacks its own `paths:`):
     - `database.instructions.md` — `applyTo: "**/entities/**/*.ts"`, `"**/repositories/**/*.ts"`, `"**/migrations/**/*.ts"`
     - `dtos.instructions.md` — `applyTo: "**/dtos/**/*.ts"`
     - `controllers.instructions.md` — `applyTo: "**/controllers/**/*.ts"`
     - `tests.instructions.md` — `applyTo: "**/*.spec.ts"`, `"**/*.test.ts"`

## Idempotency

Both files have a marker:
```markdown
<!-- GENERATED BY claude-setup-project. User edits below persist. -->
```
Generator overwrites above the marker.

User-owned files: prefix `user-*.instructions.md` — never touched.

## Known gotchas

- `.github/copilot-instructions.md` MUST be in `.github/` folder (not repo root).
- `applyTo:` frontmatter uses a single string OR array. Single string is easier to maintain.
- Globs are matched against the file being edited, not the cwd.
- `applyTo: "**"` matches everything — equivalent to repo-wide. Prefer `.github/copilot-instructions.md` for that instead.
- **`.github/prompts/*.prompt.md`** — supported for **user-invoked** reusable prompts in VS Code Copilot Chat (not auto-loaded like `copilot-instructions.md`). This adapter **does** map `.claude/commands/` / agents / skills into that folder per **§ Full artifact translation** (below). The GitHub.com web UI does not auto-load `.github/prompts/` the same way; treat prompts as in-editor workflow.

## Full artifact translation

**Authoritative mapping** (commands, agents, skills → `.github/prompts/`, hooks → `.github/hooks/*.json` native + Husky for commit/CI, rules → instructions) — this section overrides any shorter capability line at the top of this file if they appear to disagree.

### Commands — `.claude/commands/<name>.md` → `.github/prompts/<name>.prompt.md` (NATIVE)

Copilot has native reusable prompts. One file per command:

```markdown
---
mode: agent
description: Hit dev endpoint via curl and verify DTO shape
---

# /endpoint-test

<body of .claude/commands/endpoint-test.md>

Arguments: ${input:controller}
```

Invoke in Copilot Chat: type `/<name>` directly, or open the prompts picker.

Path: `.github/prompts/<command-name>.prompt.md`.

### Agents — `.claude/agents/<name>.md` → `.github/agents/<name>.agent.md` (NATIVE)

Copilot now has native custom agents. Each lands in its own `.agent.md` file:

```markdown
---
description: Reviews backend code for repository / service / controller hygiene
tools: [read, search]
model: claude-sonnet-4-6
---

# backend-reviewer

<agent body from .claude/agents/backend-reviewer.md>

**When to use**: backend code review (controller / service / repository layer).
```

Copilot's agent picker surfaces this persona; users select it from the chat UI. No "Act as ..." prefix needed — Copilot wraps the body itself.

Path: `.github/agents/<agent-name>.agent.md`.

### Skills — `.claude/skills/<name>/` → `.github/skills/<name>/` (NATIVE folder copy)

Copilot supports Agent Skills (`.github/skills/<name>/SKILL.md`) — the same shape Claude uses. Adapter copies the folder verbatim:

```
.github/skills/module-scaffold/
├── SKILL.md             # Frontmatter + body, copied 1:1 from .claude/skills/module-scaffold/SKILL.md
├── scaffold.sh          # Optional script — Copilot runs via its bash tool
└── templates/           # Sub-resources copied verbatim
```

`SKILL.md` frontmatter:

```markdown
---
name: module-scaffold
description: Scaffold a new NestJS module matching project conventions
---

<skill body>
```

Copilot loads this on-demand when the skill description matches the user's intent (progressive disclosure — full body only loads when relevant).

### Chat modes — `.claude/agents/*.md` flagged as `mode: chat` → `.github/chatmodes/<name>.chatmode.md` (NATIVE, optional)

Custom chat modes are a Copilot-native concept (custom persona + tool set + always-on for the duration of the chat). When a Claude agent's frontmatter includes `mode: chatmode-<name>` (or the project's `_translate.md` requests it), the adapter writes:

```markdown
---
description: Backend deep-dive mode — locked to read + search tools
tools: [read, search, terminal]
model: claude-sonnet-4-6
---

# backend-deep-dive

<chatmode body — usually a richer version of the agent body>
```

Path: `.github/chatmodes/<mode-name>.chatmode.md`.

If the project has no agents flagged for chatmode translation, the adapter writes nothing here — `.github/chatmodes/` is optional.

### Hooks — `.claude/hooks/*.sh` → `.github/hooks/*.json` (NATIVE) + Husky (commit/CI)

**Native support:** full ✓ — Copilot now has a lifecycle-hook system that maps 1:1 to Claude Code's hooks. It fires across agent types (Copilot CLI local + background + Cloud Agent); VS Code Copilot Chat carries the same mechanism as **Agent hooks (Preview)**. This replaces the old Husky-only fallback (Husky is retained as the commit/CI backstop only).

**Native mechanism:** `.github/hooks/*.json` at the repo root (`version: 1`), discovered by Copilot CLI, background agents, and the Cloud Agent (the Cloud Agent reads **only** `.github/hooks/*.json`). Copilot CLI additionally reads `~/.copilot/hooks/`, inline `hooks` blocks in `.github/copilot/settings.json`, and org policy files under `/etc/github-copilot/policy.d/`. Each entry is a `command` (bash/powershell script), `http` (POST payload to a URL), or `prompt` (auto-submit text on `sessionStart`) type; scripts exchange JSON over stdin/stdout. Events: `sessionStart`, `userPromptSubmitted`, `preToolUse`, `postToolUse`, `preCompact`, `subagentStart`, `subagentStop`, `agentStop` (a.k.a. `Stop`). Mapping to Claude Code:

| Claude Code hook | Copilot event | Can block? |
|---|---|---|
| `PreToolUse` | `preToolUse` | ✓ allow / deny / modify tool arguments |
| `PostToolUse` | `postToolUse` | modify result / inject context (no deny) |
| `UserPromptSubmit` | `userPromptSubmitted` | notification-only (no output processed) |
| `SessionStart` | `sessionStart` | inject context / auto-submit a prompt |
| `Stop` | `agentStop` | ✓ can block and force continuation |

**Translation of the repo's hooks** (copy `.claude/hooks/*.sh` into `.github/hooks/` and reference from the JSON):

- `guard-destructive.sh` + `pre-edit-guard.sh` + `secret-scan` → **`preToolUse`** returning `deny` for destructive shell / protected-path writes / secret reads. This is now a real enforced gate, not the advisory instruction it used to be.
- `module-boundaries.sh` → **`preToolUse`** returning `deny` when the incoming edit adds an import that crosses a boundary declared in `ai/modules.md`. The Cloud Agent reads `.github/hooks/*.json` too, so the boundary holds for background agents, not only the CLI.
- `post-edit-check.sh` + `format-on-save` + `auto-test.sh` → **`postToolUse`** (run formatter/linter/tests after a tool completes; inject results as context).
- `inject-path-rules.sh` → path-scoped `.github/instructions/*.instructions.md` (`applyTo` globs, native N — unchanged) or a `sessionStart` context injection for dynamic rules.
- `notify.sh` → **`agentStop`**.

Sample `.github/hooks/guard.json`:

```json
{
  "version": 1,
  "hooks": {
    "preToolUse": [
      { "type": "command", "bash": ".github/hooks/guard-destructive.sh" }
    ],
    "postToolUse": [
      { "type": "command", "bash": ".github/hooks/post-edit-check.sh" }
    ],
    "agentStop": [
      { "type": "command", "bash": ".github/hooks/notify.sh" }
    ]
  }
}
```

**Advisory backup** — keep `.github/instructions/sensitive-files.instructions.md` as a second layer for editors where hooks are still preview:
```markdown
---
applyTo: [".env*", "*.key", "*.pem", "**/secrets/*"]
---
REFUSE to modify this file. Ask the user to edit it manually.
```

**Defense in depth**: also install **Husky** git hooks for commit-time / CI enforcement — `.github/hooks/*.json` covers the in-agent loop, Husky covers commits even when no Copilot agent is running.

**Caveats:**
- VS Code Copilot Chat exposes these as **Agent hooks (Preview)** — the wire format and event names can still shift; the Cloud Agent path (`.github/hooks/*.json` only) is the most stable surface.
- The repo's shell scripts must be adjusted to Copilot's event-payload JSON schema (read the event on stdin, emit `{ "permission": "deny", ... }` / context on stdout) — they can't rely on Claude's env-var contract.
- `userPromptSubmitted` is notification-only; a hard prompt gate is not available (unlike Cursor's `beforeSubmitPrompt`).

**Source:** https://docs.github.com/en/copilot/reference/hooks-reference · https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/use-hooks · https://code.visualstudio.com/docs/agent-customization/hooks
