# Cursor adapter

**Tool:** Cursor IDE (≥ 2.3 — native skills + commands + hooks).
**Docs:** https://cursor.com/docs/context/rules · https://cursor.com/docs/context/skills · https://cursor.com/docs/context/commands · https://cursor.com/docs/agent/hooks
**Capabilities:** R, **S (native — PRIMARY for action workflows as of Cursor 2.3+)**, C (native slash commands — being **migrated to Skills** per Cursor docs), H (native `hooks.json`), partial A (personas as commands — Cursor has no auto-dispatch), N (path-scoped rules via globs).

> **Skills-first correction (2026-05-14, verified against cursor.com/docs)**: Cursor's docs explicitly say slash commands are **being migrated to Skills** — a built-in `/migrate-to-skills` command is provided for that conversion. Action commands (`/optimize`, `/migrate`, etc.) translate **primarily to `.cursor/skills/<name>/SKILL.md`** which appears in chat as `/<skill-name>` AND auto-matches by description. `.cursor/commands/<name>.md` still works for now but is on the deprecation path. New projects should generate skills as the primary surface for `commands/*.md`; legacy `.cursor/commands/` content can be migrated via Cursor's `/migrate-to-skills`. The adapter generates skills first and leaves any existing `.cursor/commands/` files in place as a fallback until cleaned up.

> **Cursor 2.3+ standalone goal**: a project generated by `/setup-project` with the `cursor` adapter selected MUST work end-to-end in Cursor with **no `.claude/` present**. Skills appear in Cursor's Skills picker; slash commands appear in chat (`/<name>`); hooks fire on lifecycle events; rules attach via globs. Nothing depends on Cursor reading `.claude/`.

## Target files

```
repo-root/
├── .cursor/
│   ├── rules/
│   │   ├── 00-project.mdc                    # Always-apply project rules
│   │   ├── 10-<domain>.mdc                   # Per-domain rules (glob-scoped)
│   │   └── 20-<stack>.mdc                    # Per-stack rules
│   ├── skills/                                # NATIVE — one folder per skill
│   │   └── <skill-name>/
│   │       ├── SKILL.md                       # Skill body + frontmatter
│   │       └── *.sh / *.py                    # Optional supporting scripts (copied verbatim)
│   ├── commands/                              # NATIVE — one .md per slash command
│   │   ├── <command-name>.md                  # /<command-name> in chat
│   │   └── agent-<name>.md                    # Persona invocation (Cursor has no agent dispatch)
│   └── hooks.json                             # NATIVE — lifecycle hooks
└── AGENTS.md                                  # Cursor also reads this (fallback)
```

**Legacy `.cursorrules` file:** no longer documented. Treat as write-only for backward compatibility (some older Cursor versions still read it). If present from a prior setup, keep untouched and let `.cursor/rules/*.mdc` take precedence.

**Legacy "everything-in-rules" output (pre-Apr-2026 setup-project):** older runs emitted commands/agents/skills as `command-<name>.mdc` / `agent-<name>.mdc` / `skill-<name>.mdc` files inside `.cursor/rules/`. Phase 4.8 / 4.8-DEEP migrate those to the native `.cursor/{commands,skills}/` folders on next refresh; leave any legacy `.mdc` files in place as harmless fallbacks until the user runs `--refresh`.

## File formats

### `.cursor/rules/*.mdc`
MDC (Markdown with YAML frontmatter). Activation frontmatter:
```yaml
---
description: Brief description shown in context picker
globs: ["src/**/*.ts", "apps/**/*.ts"]   # Paths this rule applies to
alwaysApply: false                         # If true, rule is always in context
---
```
Body = markdown prose with optional `@file` references:
```markdown
When editing TypeORM entities, follow:
- `@file .claude/rules/database.md`
- `@file ai/patterns/data-access.md`
```
`@file` inlines the referenced file at render time, letting us reuse the canonical rules without duplication.

### File naming convention
Prefix rules with a two-digit sort key:
- `00-` always-apply root-level
- `10-` domain-scoped (backend, frontend, database)
- `20-` stack-scoped (nestjs, vue, react)
- `30-` feature-specific (ai-integration, multi-tenancy)

## Translation recipe

For each `.claude/rules/<name>.md` + `ai/patterns/<name>.md`:

1. Decide activation mode:
   - `alwaysApply: true` → rules that apply project-wide (project-structure, jsdoc, naming).
   - `globs: [...]` → rules scoped to specific file patterns (database → `src/**/entities/**/*.ts`, controllers → `src/**/controllers/**/*.ts`).
2. Write a thin MDC file that:
   - Has the frontmatter with correct activation.
   - Body uses `@file` to include the canonical `.claude/rules/<name>.md` rather than copying content.
3. Write one `00-project.mdc` always-apply rule that points at `AGENTS.md` + top-level `ai/` files.

## Idempotency

Each generated `.mdc` has a top-of-body marker:
```markdown
<!-- GENERATED BY claude-setup-project. User edits below this line persist. -->
```
Generator rewrites everything ABOVE that line (frontmatter + `@file` refs + canonical intro); below-line user additions are preserved.

## Known gotchas

- `.mdc` extension is required (not `.md`) — Cursor won't load `.md` from `.cursor/rules/`.
- Glob patterns are evaluated against workspace root, not git root.
- Frontmatter `description` is the only thing shown in Cursor's UI — make it scannable (<60 chars).
- `@file` references resolve relative to workspace root. Broken refs silently show as blank.
- `alwaysApply: true` burns context on every request — reserve for truly universal rules.
- Nested `.cursor/rules/` in subfolders ARE supported (rules folder walks up from cwd like `.gitignore`).

## Full artifact translation

### Commands — `.claude/commands/<name>.md` → `.cursor/skills/<name>/SKILL.md` (PRIMARY) + `.cursor/commands/<name>.md` (fallback)

Per the **Skills-first correction** at the top of this adapter, action commands translate **primarily to a native Cursor Skill** at `.cursor/skills/<name>/SKILL.md` — it appears in chat as `/<name>` AND auto-matches by description, and is the surface Cursor's `/migrate-to-skills` steers slash commands toward. A `.cursor/commands/<name>.md` mirror is ALSO written as a **fallback** (still works today; on the deprecation path) so existing `/<name>` muscle-memory keeps working until the user runs Cursor's `/migrate-to-skills` cleanup.

**Primary** — `.cursor/skills/<name>/SKILL.md` (needs a `name:` field the source command lacks, so this is LLM-authored, not a raw copy):

```markdown
---
name: endpoint-test
description: Hit dev endpoint via curl and verify DTO shape — use when testing a controller's response shape
---

# /endpoint-test

<body of .claude/commands/endpoint-test.md>

Arguments: the user's text after `/endpoint-test` is the skill's input.
```

**Fallback** — `.cursor/commands/<name>.md` (1:1 mirror of the source, no prefix — Cursor recognises the file directly):

```markdown
---
description: Hit dev endpoint via curl and verify DTO shape
---

# /endpoint-test

<body of .claude/commands/endpoint-test.md>

Arguments: $ARGUMENTS (Cursor expands the user's typed args after `/endpoint-test`).
```

User invokes by typing `/endpoint-test <controller>` in Cursor chat (resolves to the skill, or the command-fallback if skills aren't migrated yet) — exactly as in Claude Code.

Paths: `.cursor/skills/<name>/SKILL.md` (primary) + `.cursor/commands/<name>.md` (fallback mirror — same filename, no prefix).

### Agents — `.claude/agents/<name>.md` → `.cursor/commands/agent-<name>.md` (NATIVE — translated as a command)

Cursor has no auto-dispatch agent system, so personas land in the commands folder with an `agent-` prefix so users can invoke them as `/agent-<name>`:

```markdown
---
description: Act as the backend-reviewer persona
---

# /agent-backend-reviewer

Adopt this persona for the conversation that follows.

**Persona**: <agent body from .claude/agents/backend-reviewer.md>
**When to use**: backend code review (controller/service/repository layer).

**Tools available in Cursor**: Cursor's built-in Edit / Read / Bash via composer. There is no equivalent to Claude Code's Agent tool — you ARE the agent while this command is active.
```

Path: `.cursor/commands/agent-<name>.md`.

### Skills — `.claude/skills/<name>/SKILL.md` → `.cursor/skills/<name>/SKILL.md` (NATIVE folder copy)

Cursor 2.3+ natively reads `.cursor/skills/<name>/SKILL.md`. The adapter copies the entire skill folder verbatim — including any supporting scripts:

```
.cursor/skills/module-scaffold/
├── SKILL.md            # Frontmatter + body, copied 1:1 from .claude/skills/module-scaffold/SKILL.md
├── scaffold.sh         # Copied verbatim
└── templates/          # Any sub-resources copied verbatim
    └── module.template.ts
```

`SKILL.md` frontmatter (Cursor accepts the same shape Claude does):

```markdown
---
name: module-scaffold
description: Scaffold a new NestJS module matching project conventions
---

<skill body>
```

Cursor surfaces this skill in its Skills picker. When the user activates it, Cursor's agent loads the body as procedure context; supporting scripts are runnable via the Bash tool the same way Claude Code runs them.

### Hooks — `.claude/hooks/*.sh` → `.cursor/hooks.json` (NATIVE)

Cursor 2.3+ has lifecycle hooks via `.cursor/hooks.json`. Translate each Claude hook into the matching Cursor event:

| Claude Code hook | Cursor `hooks.json` event |
|---|---|
| `PreToolUse` (block / validate before tool runs) | `beforeToolCall` |
| `PostToolUse` (lint after edit) | `afterToolCall` |
| `SessionStart` (briefing) | `sessionStart` |
| `Stop` (session log) | `sessionEnd` |

Sample `.cursor/hooks.json` (copy `.claude/hooks/*.sh` verbatim into `.cursor/hooks/` as the `command` payload — keep them executable; the JSON points at them):

```json
{
  "$schema": "https://cursor.com/schemas/hooks.v1.json",
  "version": 1,
  "_generator": "claude-setup-project",
  "hooks": {
    "beforeToolCall": [
      { "name": "guard-destructive", "command": ".cursor/hooks/guard-destructive.sh", "timeout": 5000 },
      { "name": "pre-edit-guard",    "command": ".cursor/hooks/pre-edit-guard.sh",    "timeout": 5000 }
    ],
    "afterToolCall": [
      { "name": "post-edit-check",   "command": ".cursor/hooks/post-edit-check.sh",   "timeout": 30000 }
    ],
    "sessionStart": [
      { "name": "briefing",          "command": ".cursor/hooks/session-start.sh",     "timeout": 10000 }
    ],
    "sessionEnd": [
      { "name": "session-log",       "command": ".cursor/hooks/session-stop.sh",      "timeout": 5000 }
    ]
  }
}
```

Place the actual scripts at `.cursor/hooks/<name>.sh` (copy from `.claude/hooks/<name>.sh` — same content; Cursor invokes them with the same env).

**Defense in depth**: also install Husky git hooks for commit-time enforcement (lint, .env guard) — `.cursor/hooks.json` covers in-IDE editing, Husky covers commits/CI even when the user is not in Cursor. Both layers should reference the same scripts where possible.

### Rules — `.claude/rules/<name>.md` → `.cursor/rules/<NN>-<name>.mdc` (existing flow — unchanged)

This part of the contract did not change. See **§ Translation recipe** above for the rules side; only commands / skills / hooks moved to native folders.
