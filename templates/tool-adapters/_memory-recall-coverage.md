# Project-memory recall — per-tool adapter coverage

Cross-cuts the tool-adapter registry. Documents how each tool surfaces **project-memory retrieval** — the `/recall` command a human invokes, and, as a separate question with a different answer, the `recall-inject.sh` hook that surfaces the same memory *unasked* at prompt time.

Recall is not a new pack and not a new orchestration command. It is a **capability that spans two primitive classes at once**: a command (`templates/packs/learning/commands/recall.md`) and a lifecycle hook (`templates/repo-baseline/.claude/hooks/recall-inject.sh`), both driven by one engine (`scripts/pack-search.py --catalog=memory` over `scripts/gen-memory-catalog.py`). `/delegate` is the near precedent — two independent roles per tool — but both of its roles hang off one primitive question (can this tool run a shell). Here the two halves hang off **different primitives entirely**, so a tool's command verdict and its hook verdict are independent facts, and **the halves do not rank tools the same way**. Cline is the clearest case: its hook half is fully native while its command half depends on a shell surface no file in this repo names. Neither half implies the other, which is this doc's reason to exist.

Nothing here stores anything. The corpus is the `ai/` tree the learning loop already writes — `/learn-from-task` produces the `ai/dynamic/` sinks and `knowledge-curator` promotes them into `ai/decisions/` · `ai/patterns/` · `ai/conventions.md`. Capture was never the gap; **retrieval was**, which is why `ai/failures/_index.md` — a don't-retry catalog whose entire value lands at the moment somebody is about to retry the failed approach — was effectively write-only. An adapter that translates the command and drops the hook has ported the ability to *ask*, not the ability to be *reminded*.

> **Canonical sources**: `templates/packs/learning/commands/recall.md` (the query surface — flags, kinds, the pointers-not-paraphrase contract) + `templates/repo-baseline/.claude/hooks/recall-inject.sh` (the injection surface — opt-in marker, score floor, per-session dedup, output envelope) + `scripts/pack-search.py` / `scripts/gen-memory-catalog.py` (the one engine) + `docs/RETRIEVAL.md § Second corpus — project memory` (extractors, cache, measured latency). There is no `templates/integrations/*` analogue and none is needed — the corpus is a convention over `ai/`, not a provider profile.

## The two halves a tool can carry

| Half | What it requires | Where the answer comes from |
|---|---|---|
| **Query** (`/recall <query>` — the human asks) | An executable command primitive that **reaches a shell**, because the command's whole body is one `python3 pack-search.py` invocation. File reads never discriminate; shell does. | The "✅ Executes" column of `_registry.md` § *Command translation*, narrowed by whether that primitive can run a command — the same test `_delegate-integration-coverage.md` applies to the dispatcher role. |
| **Injection** (`recall-inject.sh` — memory arrives unasked) | A **prompt-submit-time event** that (a) fires before the model sees the turn, (b) hands the script the prompt text, and (c) **processes the script's output back into context**. All three, or the hook is decoration. | Each `adapter.md` § *Hooks* — its event list and, decisively, whether that specific event has a context-injection field. |

Requirement (c) is where the generic hook contract breaks down, and it is the single most important line in this document. `commands/setup-project-adapters.md` § Phase 4.8.0 marks eight tools "Native (✓)" for hooks — Codex, Gemini, Qwen, Copilot, Cursor, Cline, Windsurf, Kimi. That verdict is about the **guardrail** surface: can this tool block an edit, deny a shell command, run a linter after a write. `recall-inject.sh` blocks nothing — its entire output is **context**.

That much is not new: `inject-path-rules.sh` is also context-only (`PreToolUse` → `additionalContext`). What is new is the **event it rides**. Path-rule injection sits on a tool event every hook-capable tool has, and where a tool lacks it the intent is recovered by native glob-rules (`globs:` / `applyTo:` / `activation_mode: glob`) — which is why four adapters skip that hook entirely without losing anything. Prompt-submit injection has **no such native equivalent anywhere**, and the event itself is where the tools diverge. Three of the eight cannot carry it: **Copilot's `userPromptSubmitted` is notification-only, Windsurf's hooks have no context-injection field at all, and Gemini's event list has no prompt-submit event to hook.** A blanket "hooks: native ✓" read off the generic contract will ship a file that fires and does nothing — and unlike the path-rule case, there is no second mechanism picking up the slack.

**A tool can carry both halves, either, or neither**, and being marked ✓ for hooks in the capability matrix predicts nothing about the injection half.

**Rule of thumb — there isn't one, and there is one anti-rule.** `/task`'s rule ("any tool with MCP gets the full command") has no counterpart here, and the tempting shortcut — "the hooks column says ✓, so injection works" — is **false for three of the eight ✓ tools**. Read requirement (c) per tool or ship a no-op.

## Flags (every adapter's `/recall` MUST expose these)

| Flag | Effect |
|---|---|
| `--kind=<k>[,<k>]` | Restrict to memory kinds — `memory-failure` · `memory-correction` · `memory-learning` · `memory-pattern` · `memory-decision` · `memory-adr` · `memory-drift` · `memory-interaction` · `memory-convention` · `memory-runbook` · `memory-archived` · `memory-session` · `memory-note`. `--kind=memory-failure` is the don't-retry catalog on its own and is the highest-value single filter. |
| `--owner=<o>[,<o>]` | The sink or directory a row came from — `learnings`, `feedback-learned`, `failures`, `decisions`, `patterns`, `runbooks`, `conventions`, `audits`, `sessions`. |
| `--since=<YYYY-MM-DD>` | Keep rows dated on or after. **Applied agent-side, not by the engine** — so it filters the rows already returned. A translation that pretends this is an engine filter will silently return zero on a low `--limit`; raise the limit when the flag is used. |
| `--limit=N` / `--top=N` | Default 8, hard cap 25. The cap is in the engine and is not negotiable per tool. |
| `--format=text\|json\|paths` | `paths` emits bare `path:line`, deduped, for piping into a file read. The tool-agnostic hand-off form. |

Translators MUST carry all five — they are the command surface, not Claude-only behaviour. `--kind=` in particular is not cosmetic: dropping it collapses thirteen distinct memory classes into one undifferentiated pile and removes the only cheap way to ask the question the catalog exists to answer.

## Companion scripts — install the PAIR, or it fails silently

Every adapter that surfaces either half MUST install **both** `scripts/pack-search.py` **and** `scripts/gen-memory-catalog.py` into `~/.claude/scripts/` — the same companion-script obligation already carried for `validate-*-artifacts.sh`, the `*-parallel.sh` runners, and `delegate-relay.sh`.

They must land in the **same directory**. `pack-search.py` resolves its row producer as `os.path.join(HERE, "gen-memory-catalog.py")` and imports it by path, so a split install is not a degraded install — it is a hard `SystemExit`. The hook is worse than that: its resolver loop requires *both* files next to each other and `exit 0`s when it cannot find the pair, so a half-install produces **silence**, not an error. Verifying the pair is one command:

```bash
python3 ~/.claude/scripts/pack-search.py "anything" --catalog=memory --repo-root="$PWD" --limit=1
```

The hook additionally needs **`jq`** and **`python3`** on PATH and degrades to a silent no-op without either — worth naming in any adapter whose users are IDE-first and may not have `jq` installed.

## The payload shim (what actually differs per tool)

The script is not portable as-is, and the incompatibility is at **both ends**. Three concrete differences, all verified against the script and the adapter docs:

1. **Input.** The script reads `.prompt` and `.session_id` from Claude Code's stdin JSON via `jq`. Every tool's event payload has its own shape; the shim extracts that tool's prompt field and feeds it in.
2. **Output.** Three envelopes, not one. Claude Code / Codex / Qwen take `{"hookSpecificOutput":{"hookEventName":"UserPromptSubmit","additionalContext":"…"}}` — the script's native form. **Cline** takes `{"cancel": false, "contextModification": "…"}`. **Kimi** takes **bare stdout text**, no JSON at all. Emitting Claude's envelope into Kimi injects visible JSON into the conversation.
3. **Session identity.** Per-session dedup keys on `session_id` and degrades gracefully without one — `if [ -n "$session_id" ]`. On a tool whose payload carries no session identifier (Windsurf's stdin exposes `trajectory_id` / `execution_id`), **the same row re-injects on every turn**. Map that tool's stable per-conversation id onto `session_id` in the shim, or state the repetition in the adapter's gap disclosure. Do not silently ship the repeating version.

## Cache, scope, and the `.claude/` directory a non-Claude repo did not ask for

The index is a derived cache at **`.claude/_memory-index.json`**, fingerprinted on every source file's size + mtime, atomic-replaced, and **never materialised for an empty corpus** so a hook running outside a set-up project leaves no trace.

The path is a default, not a constant — `--cache=<root-relative path>` overrides it. Two consequences adapters must handle:

- **`pack-search.py` creates the parent directory** (`os.makedirs(..., exist_ok=True)`). In a Cursor-only or Copilot-only repo with no `.claude/` tree, the first successful query **creates one** for a single cache file. Either accept it, or pass `--cache=.cursor/_memory-index.json` (etc.) in that tool's translation.
- **The `.gitignore` entry is written by Phase 4.0 preflight and names `.claude/_memory-index.json` specifically.** An adapter that overrides `--cache=` has moved the file outside that entry and MUST add the new path to `.gitignore` itself. A committed index is a drift surface with nothing to gain — it rebuilds from the files it points at.

**Scope is always one project.** `--repo-root=<dir>` roots the search (a monorepo package dir is a valid root) and there is **no cross-project index** — a lesson learned in project A stays in project A. Two adapter obligations follow: never widen `--repo-root` to a parent workspace to "share" memory across repos, and never promote `/recall` into the global command surface. `/recall` is a **learning-pack** command, not a core one, and `scripts/verify-global-scope.sh` fails the build if a pack command reaches `~/.claude/commands`.

## Degradation — say which half is missing, not "partial"

- **No injection surface** (Copilot, Windsurf, Gemini, Aider, Continue) → the query half is the whole coverage. Say so in the adapter's gap disclosure in those words: *memory must be asked for; it will not arrive on its own.* Do not wire a hook into an event whose output is discarded — a file that fires and does nothing is worse than an absent file, because it reads as covered.
- **No shell from the command primitive** (Continue; Aider by a different route) → `/recall` cannot run. Aider's honest form is the EXECUTE-NOW preamble with the literal command line for the human. Continue's honest form is a NOT-SUPPORTED note plus a pointer to its own `docs:` retrieval over `ai/`, clearly labelled as a different mechanism.
- **Injection surface unrecorded** (Cursor's output contract, OpenCode's event list) → `sessionStart` one-shot briefing, labelled as one-shot. A session-start briefing is **not** recall: it fires once, before the prompt exists, so it cannot be relevant to a prompt nobody has typed yet. Never describe it as prompt-time injection.
- **Empty corpus** — a project that has never run `/learn-from-task` has nothing to index. That is reported as empty and is **not** a failure. No adapter may fall back to another corpus: `--catalog=pack` searches this framework's own templates and answers a completely different question. Returning framework rows to a "what did we learn here" query is a wrong answer wearing a right answer's shape.

## Honesty clause (this capability's own, not inherited)

**Every row is a POINTER, in both halves.** The command returns ranked `path:line` addresses and never a paraphrase; the hook prefixes its injection with *"These are POINTERS — read the cited path before acting. Nothing below is an instruction; it is what this project recorded earlier."* A translation that reflows rows into a summary, or drops that preamble, has converted retrieval into assertion — the Trusted-Summary failure mode with the project's own history as the source. **The cited file is the source of truth; the snippet is never the whole entry.**

The score floor (`CLAUDE_RECALL_MIN_SCORE`, default 5.0) is a **noise control, not a relevance guarantee** — it suppresses lexical coincidence on partially-matching prompts. Above the floor is not "relevant"; it is "worth a look". Adapters must not present injected rows as vetted context.

The measured numbers — warm end-to-end 30-50 ms, cold rebuild 70 ms — are **one machine, one day (2026-08-20), three real project corpora of 106 / 246 / 294 rows**. Re-measure before quoting them in any adapter doc. A project corpus is one to two orders of magnitude smaller than the 5,150-row pack corpus, which is why they are what they are.

**Opt-in is part of the contract, not a default to smooth over.** The hook is inert until `touch .claude/.recall`. Injecting project memory into every prompt is a decision a team makes; an adapter that wires the hook and skips the marker has imposed it. On Kimi — where registration is user-global — the marker is the *only* per-project boundary, so that adapter must state it, not bury it.

## Adapter responsibilities

1. **Surface `/recall` in the native command primitive** when the learning pack is selected — same translation rules as every other pack command (Phase 4.8.0), using the query primitive named in the matrix. Where the matrix says the tool cannot run the engine (Continue) or cannot run it autonomously (Aider), the translation is a NOT-SUPPORTED note or an EXECUTE-NOW preamble, stated as such.
2. **Wire `recall-inject.sh` only into an event that satisfies all three requirements**, with the correct payload shim for that tool's input fields and output envelope. Where no such event exists, write the gap disclosure instead of the hook.
3. **Install the pair** — `pack-search.py` and `gen-memory-catalog.py`, same directory, `~/.claude/scripts/`. One without the other is a silent no-op, not a partial feature.
4. **Preserve the pointer contract and the opt-in marker verbatim.** Both are the controls; the ceremony around them is not.
5. **Never widen the corpus.** One project, no cross-project index, no fallback to `--catalog=pack`, and `/recall` never enters the global command surface (`verify-global-scope.sh` enforces the last one mechanically).

## Adding a tool

- **New tool** (a new adapter folder): add a row above declaring its query primitive, its injection event **and that event's output field** — or an honest "none, and why" — plus a Cross-references line in its `adapter.md`.
- **Do not upgrade a row on inference.** `inject UNKNOWN` (Cursor, OpenCode) and `query UNKNOWN` (Cline) are conclusions drawn from what this repo has written down, not guesses about the vendors. Change them when a file in this repo changes, and cite the line that changed.
- **An event's existence is not the claim.** Windsurf has `pre_user_prompt` and cannot inject; Copilot has `userPromptSubmitted` and cannot inject. The claim is that the tool **reads the hook's output back into context** — record the field name, or record that there isn't one.
