# Gemini CLI adapter

**Tool:** Google Gemini CLI.
**Docs:** https://github.com/google-gemini/gemini-cli
**Capabilities:** R only — no agents, commands, hooks, skills.

## Target files

```
repo-root/
├── GEMINI.md                          # Project context (Gemini CLI reads this automatically)
└── .gemini/                           # Optional state + local config (don't write by default)
```

Global Gemini config lives at `~/.gemini/settings.json` — out of scope for per-repo setup.

## File formats

### `GEMINI.md`
Plain markdown. No frontmatter. Loaded automatically by Gemini CLI when run in the repo directory. Parallel to AGENTS.md but Gemini-specific.

Recommended structure (same as AGENTS.md but can reference Google-specific tools like Vertex AI or Google Sheets integrations if present):
- Project overview
- Architecture
- Key commands
- Conventions (MUST / MUST NOT)
- Code style
- Testing
- Deeper context pointers

## Translation recipe

1. Detect if `AGENTS.md` already exists.
2. If yes: write `GEMINI.md` as a thin pointer file:
   ```markdown
   # <Project> — Gemini context

   See `AGENTS.md` for universal project rules. This repo uses that standard.

   ## Gemini-specific notes
   (leave empty unless the project has Gemini-specific integrations — e.g., Vertex AI, GenAI SDK, Gemini function-calling tools)
   ```
3. If no: write a full `GEMINI.md` with the same content AGENTS.md would have.

## Known gotchas

- `GEMINI.md` is the only file Gemini CLI reads from the repo by default. No folder-based rules.
- `.gemini/` folder exists for state (cached responses, auth) — don't write project-level config there.
- Gemini CLI also reads `~/.gemini/settings.json` globally. Per-user, not per-repo.
- If project uses Google Cloud / Vertex AI specifically, add Gemini-specific integration notes (model names, auth via `GOOGLE_APPLICATION_CREDENTIALS`, etc.) in a dedicated section.

## Full artifact translation

Same pattern as Codex adapter — Gemini CLI has no native commands/agents/skills/hooks. Translate each into a section of `GEMINI.md`.

### Commands → `## Invokable commands` in GEMINI.md

```markdown
## Invokable commands (ask Gemini to "run <name>")

### endpoint-test
<body — trimmed>
```

### Agents → `## Named personas` in GEMINI.md

Same format as Codex adapter.

### Skills → `## Named procedures` in GEMINI.md

Same format as Codex adapter.

### Hooks → `## Driver-dependent safety` in GEMINI.md + git hooks

Same disclosure pattern as Codex.

### If AGENTS.md already covers everything

When the project has `AGENTS.md` populated with all 4 artifact sections, the `GEMINI.md` body can simply be:

```markdown
<!-- GENERATED BY claude-setup-project. User edits below persist. -->

# <Project> — Gemini context

This project uses the AGENTS.md cross-tool standard. See `AGENTS.md` for:
- Project rules
- Invokable commands
- Named personas (agents)
- Named procedures (skills)
- Driver-dependent safety (hooks fallback)

## Gemini-specific notes

(none — or specify Vertex AI / GenAI SDK / Gemini function-calling integrations if this project uses them)
```

Avoids duplicating content across two files.
