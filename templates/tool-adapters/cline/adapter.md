# Cline / Roo adapter

**Tool:** Cline (VS Code extension) — Roo is a Cline fork with similar conventions.
**Docs:** https://docs.cline.bot/features/cline-rules · https://docs.cline.bot/customization/workflows
**Capabilities:** R, C (native — `.clinerules/workflows/` slash commands). No native agents / hooks / skills.

> **Cline standalone goal**: a project generated by `/setup-project` with the `cline` adapter selected MUST work end-to-end in Cline with **no `.claude/` present**. Rules attach automatically; slash commands appear in chat (`/<workflow-name>`); agents and skills fall back to documented sections in `.clinerules/` (Cline has no native primitive for them).

## Target files

```
repo-root/
├── .clinerules/                              # Folder (preferred over legacy single file)
│   ├── 00-project.md                         # Always-loaded project rules
│   ├── 10-<domain>.md                        # Per-domain rules
│   ├── 20-<stack>.md                         # Per-stack rules
│   ├── 81-agents.md                          # Persona index (no native dispatch)
│   ├── 82-skills.md                          # Procedure index (no native skills)
│   └── workflows/                             # NATIVE — Cline slash commands
│       └── <workflow-name>.md                # Becomes /<workflow-name> in Cline chat
└── AGENTS.md                                  # Cline also reads this as fallback
```

**Legacy single-file `.clinerules`:** older Cline versions read a single file. Treat as deprecated; folder-style is now documented default. If `.clinerules` file exists from a prior setup, leave it and write folder-style alongside (folder takes precedence).

## File formats

### `.clinerules/*.md`
Plain markdown. No frontmatter required — Cline loads every `.md` + `.txt` in the folder alphabetically. Ordering matters (use `00-`, `10-`, `20-` prefix for predictable precedence).

Cline is reported to read `.cursorrules`, `.windsurfrules`, and `AGENTS.md` from repo root as additional rule sources — verify against https://docs.cline.bot/features/cline-rules before relying on it. If true, avoid duplicating content across these files: Cline concatenates everything it finds, and duplicates waste context.

## Translation recipe

1. **`.clinerules/00-project.md`** — project-wide rules:
   - Read-before-edit principle
   - Architecture summary
   - Top 5-10 MUST / MUST NOT rules
2. **`.clinerules/<NN>-<domain>.md`** — one file per `.claude/rules/<domain>.md` (one-to-one, **REQUIRED by Phase 4.8.0 contract**, not optional). `<NN>` ∈ {10..79}:
   - Copy from `.claude/rules/<domain>.md` verbatim (Cline doesn't support includes).
   - Numeric prefix groups related rules (10-19 = always-relevant; 20-29 = stack-specific; 30-79 = domain/feature-specific).
3. **`.clinerules/20-<stack>.md`** — stack-specific (nestjs, vue, react):
   - Copy relevant pack rules.

Since Cline has no glob-based scoping, path-scoped rules must be written as prose ("When editing database code...").

## Idempotency

Each generated `.md` has a marker:
```markdown
<!-- GENERATED BY claude-setup-project. User edits below persist. -->
```
Generator overwrites everything above the marker.

User-owned convention: prefix custom files with `90-user-*.md`. Generator never touches those.

## Known gotchas

- Numeric prefix isn't enforced by Cline — it just loads alphabetically. Stick to two-digit prefixes for consistency.
- Cline reads ALL of: `.clinerules/*.md`, `.clinerules` (file), `.cursorrules`, `.windsurfrules`, `AGENTS.md`. Content duplicated across multiple sources is a context-waste risk.
- No character limit documented but keep total rule budget under ~15k tokens; Cline's performance degrades with long rule stacks.
- Cline supports `/newrule` slash command to create rules interactively. Leave `.clinerules/90-user-*.md` namespace free for that.

## Full artifact translation

### Commands — `.claude/commands/<name>.md` → `.clinerules/workflows/<name>.md` (NATIVE)

Cline has native slash commands via `.clinerules/workflows/*.md`. The filename (minus `.md`) is the slash command. One file per command, body copied 1:1 from `.claude/commands/<name>.md`:

```markdown
<!-- GENERATED BY claude-setup-project. User edits below persist. -->

# /endpoint-test

<body of .claude/commands/endpoint-test.md>

Arguments: the user's typed args after `/endpoint-test`.
```

User invokes: `/endpoint-test OrderController` in Cline chat — exactly as in Claude Code.

Path: `.clinerules/workflows/<command-name>.md` (no prefix, no extension stripping).

> **Backward-compat**: pre-Apr-2026 setup-project also wrote a catalog at `.clinerules/80-commands.md`. Phase 4.8 / 4.8-DEEP keep that catalog as a fallback for older Cline builds; new setups can drop it once no Cline pre-3.0 user is in scope.

### Agents — `.claude/agents/*.md` → `.clinerules/81-agents.md` persona index

```markdown
# Named personas (invoke by asking Cline to "act as <agent-name>")

## backend-reviewer
**Persona**: <agent body>
**When to use**: <from description>

## tenant-isolation-reviewer
**Persona**: ...
**When to use**: ...
```

User invokes: "Act as the backend-reviewer and review this diff."

### Skills — `.claude/skills/<name>/SKILL.md` → `.clinerules/82-skills.md`

```markdown
# Procedures (skills)

## module-scaffold
<body of .claude/skills/module-scaffold/SKILL.md>
Shell steps in `.claude/skills/module-scaffold/*.sh` — user runs manually.

## schema-diff
<body of .claude/skills/schema-diff/SKILL.md>
```

### Hooks — `.claude/hooks/*.sh` → git hooks + `.clinerules/00-project.md` disclosure

Cline has no lifecycle hooks:

1. **Git hooks** → `.husky/pre-commit` covers lint + .env guard.
2. **Session-start** → `.clinerules/00-project.md` top line: "Always read `ai/status.md` before starting work."
3. **Stop / session-log** → document in project rules: "Append to `ai/dynamic/session-log.md` when changes exceed 5 files."
4. **Disclose** in `.clinerules/00-project.md`:
   ```markdown
   ## Driver gaps (Cline vs Claude Code)
   This project relies on Claude Code hooks for:
   - Post-edit linting → replaced by Husky + IDE save-lint.
   - Pre-edit blocks on `.env*` → replaced by `.gitignore` + git hook (soft).
   - Session-start briefing → replaced by this always-read rule.
   - Automatic session log → manual.
   ```
