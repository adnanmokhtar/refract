# Aider adapter

**Tool:** Aider (https://aider.chat) — terminal pair programmer.
**Docs:** https://aider.chat/docs/config/aider_conf.html
**Capabilities:** R only — no agents, no commands, no hooks, no skills.

Aider is the minimalist of the adapter set (see `_registry.md`). One config file, one conventions file. Everything else is CLI flags or env vars.

## Target files

```
repo-root/
├── .aider.conf.yml                    # Main config
├── CONVENTIONS.md                     # Project conventions (loaded via read:)
├── .aiderignore                       # Files Aider should never touch (like .gitignore)
└── (optional) .aider.model.settings.yml
```

## File formats

### `.aider.conf.yml`
YAML. Key fields:
```yaml
# Model config
# model: anthropic/claude-sonnet-4-6
# (leave commented — user picks; env vars take precedence)

# Files always loaded as context (read-only) — canonical order, must match Phase 4.8.0 contract
read:
  - CONVENTIONS.md          # Aider-specific compacted ruleset (this adapter writes it)
  - AGENTS.md               # cross-tool universal anchor (codex adapter writes it)
  - ai/README.md            # navigation
  - ai/status.md            # current phase + recent changes
  # - ai/business-domain.md # APPEND THIS LINE if the project has a populated business-domain.md

# Auto-commit behavior
auto-commits: false                    # Let user commit; don't surprise-commit
dirty-commits: false

# Lint command run after edits
lint-cmd: "<project-lint-cmd>"         # e.g. "pnpm lint" / "npm run lint"

# Test command
test-cmd: "<project-test-cmd>"         # e.g. "pnpm test"

# Disable the browser UI by default
gui: false
```

### `CONVENTIONS.md`
Plain markdown. Aider reads this verbatim as "here are the rules of this codebase." Keep under ~3k tokens or Aider's context window gets crowded.

Structure:
1. **Project intro** — one paragraph.
2. **Architecture** — one paragraph pointing at `ai/architecture.md`.
3. **Key conventions** — bullet list of MUST / MUST NOT.
4. **Pointer to deeper docs** — `AGENTS.md`, `ai/patterns/`, `.claude/rules/`.

### `.aiderignore`
Same syntax as `.gitignore`. Typical entries:
- `.env*`
- `node_modules/`
- `dist/` / `build/`
- Database migrations (historical, shouldn't edit)
- `*.lock` files

## Translation recipe

1. **`CONVENTIONS.md`** — flatten the most critical rules from `.claude/rules/*.md` into a single digestible file. Hierarchy:
   - Read-before-edit + code-style rules (always relevant).
   - Architecture layers + naming (relevant for most edits).
   - Domain rules (tenant-safety, etc.) — one sentence each with `@file` style pointer.
2. **`.aider.conf.yml`** — write with `read:` list enumerating `CONVENTIONS.md`, `AGENTS.md`, `ai/README.md`, `ai/status.md`. Omit model selection.
3. **`.aiderignore`** — start from baseline (`.env*`, `node_modules/`, `dist/`) + append project-specific (migrations, lock files, build outputs detected from codebase profile).

## Idempotency

`CONVENTIONS.md` has a generator-owned top section ended by `<!-- GENERATOR END -->`. User prose below the marker persists.

`.aider.conf.yml` `read:` list is regenerated (user can add their own entries — generator preserves them by detecting lines without the `# generated` suffix).

## Known gotchas

- Aider's `read:` list is read-only context — good for conventions, not good for files Aider should EDIT.
- `lint-cmd` / `test-cmd` run automatically after changes. If they're slow or noisy, Aider becomes frustrating. Tune per project.
- `CONVENTIONS.md` is loaded in every session — keep it tight. Aider burns more tokens on long conventions files than Claude Code does on CLAUDE.md.
- No nested / path-scoped rules. Everything in `CONVENTIONS.md` applies globally.
- Aider uses LiteLLM under the hood. Model strings follow LiteLLM's format (`openai/...`, `anthropic/...`, `deepseek/...`, `moonshot/...` for Kimi).

## Full artifact translation

### Commands — `.claude/commands/*.md` → named sections in `CONVENTIONS.md`

Aider has no slash-command system. Translate each command into a named section of `CONVENTIONS.md` under `## User-invoked procedures`:

```markdown
## User-invoked procedures

### endpoint-test <controller>
When user asks "run endpoint-test for <X>" or similar, follow this procedure:

<body of .claude/commands/endpoint-test.md>
```

User invokes verbally: "Please run the endpoint-test procedure on OrderController." Aider reads `CONVENTIONS.md` (via `read:` in `.aider.conf.yml`) and executes.

### Agents — `.claude/agents/*.md` → personas in `CONVENTIONS.md`

Same pattern:

```markdown
## Named personas

### backend-reviewer
When user asks "act as backend-reviewer" (or you're asked to review backend code):

**Persona**: <agent body>

**When to use**: <from agent frontmatter description>
```

User invokes: "Act as the backend-reviewer and look at the latest commit."

### Skills — `.claude/skills/<name>/SKILL.md` → runbook entries in `CONVENTIONS.md`

```markdown
## Runbook procedures

### module-scaffold
Follow this when user asks to create a new module:

<body of .claude/skills/module-scaffold/SKILL.md>

Shell scripts: `.claude/skills/module-scaffold/*.sh` — user runs these manually in a separate terminal.
```

### Hooks — `.claude/hooks/*.sh` → Aider's `lint-cmd` + `test-cmd` (partial)

Aider has two hook-like knobs in `.aider.conf.yml`:

```yaml
lint-cmd: "pnpm lint"           # runs after each edit
test-cmd: "pnpm test"           # can run after edits with --auto-test
```

These cover `post-edit-check.sh` use case. For everything else (pre-edit guards, session-start, Stop):

1. **Pre-edit guards** → `.aiderignore` blocks Aider from touching `.env*`, migrations, etc.:
   ```
   .env*
   prisma/migrations/
   database/migrations/
   *.lock
   ```
2. **Session-start / Stop** → not replicable. Note in `CONVENTIONS.md`:
   ```markdown
   ## Session discipline
   Before starting: read `ai/status.md`.
   After work: append a bullet to `ai/dynamic/session-log.md` with branch + changed files.
   ```
3. **Flag non-covered hooks in `CONVENTIONS.md`** under a dedicated section so the user knows the safety gap.

**Naming keeps CONVENTIONS.md tight**: keep each command/agent/skill description ≤10 lines. Aider loads the full file on every session — bloat kills token budget.
