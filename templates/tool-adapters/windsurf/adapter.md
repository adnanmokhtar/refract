# Windsurf adapter

**Tool:** Windsurf (Codeium's IDE).
**Docs:** https://docs.windsurf.com/windsurf/cascade/memories · https://docs.windsurf.com/windsurf/cascade/workflows · https://docs.windsurf.com/windsurf/cascade/hooks
**Capabilities:** R, C (native — `.windsurf/workflows/` slash commands), **H (native hooks — `.windsurf/hooks.json`, 12 lifecycle events with pre-hook blocking)**. Activation-mode frontmatter for rule scoping. No native agents / skills (translated).

> **Windsurf standalone goal**: a project generated by `/setup-project` with the `windsurf` adapter selected MUST work end-to-end in Cascade with **no `.claude/` present**. Rules attach via activation modes; slash commands appear in chat (`/<workflow-name>`); agents/skills fall back to trigger-word rules.

## Target files

```
repo-root/
├── .windsurf/
│   ├── rules/
│   │   ├── 00-project.md                       # always-loaded project rules
│   │   ├── 10-<domain>.md                      # per-domain rules (glob activation)
│   │   ├── 20-<stack>.md                       # per-stack rules
│   │   ├── 81-agents.md                        # persona index (trigger_words activation)
│   │   └── 82-skills.md                        # procedure index (trigger_words activation)
│   └── workflows/                               # NATIVE — Cascade slash commands
│       └── <workflow-name>.md                  # Becomes /<workflow-name> in chat
└── AGENTS.md                                    # Windsurf also reads this
```

**Global rules (per-user, not per-repo):** `~/.codeium/windsurf/memories/global_rules.md` — out of scope for `/setup-project` (user-level, not project-level).

**Legacy `.windsurfrules` file at repo root:** older docs mention this. Current Windsurf reads `.windsurf/rules/*.md` folder. Treat root-level `.windsurfrules` as deprecated — don't write it, but leave untouched if it exists.

## File formats

### `.windsurf/rules/*.md`
Markdown with activation-mode frontmatter:
```yaml
---
activation_mode: always              # always | manual | trigger_words | glob
trigger_words: ["database", "query"] # for activation_mode: trigger_words
globs: ["src/**/*.ts"]               # for activation_mode: glob
---
```

Activation modes:
- `always` — always loaded (reserve for universal project rules)
- `manual` — loaded when user invokes the rule by name
- `trigger_words` — auto-activates when conversation mentions any trigger word
- `glob` — activates when editing file matching the glob pattern

## Translation recipe

1. **`.windsurf/rules/00-project.md`** — `activation_mode: always`, project-wide essentials (rules with **no** `paths:` frontmatter — the always-loaded foundation).
2. **Authoritative `paths:` (preferred).** If a source `.claude/rules/<name>.md` carries `paths:` frontmatter (a YAML glob list, e.g. `migration-safety.md`), emit `activation_mode: glob` with `globs:` copied **verbatim** from `paths:` — the rule declared its own scope; do not re-infer it.
3. **`.windsurf/rules/10-<domain>.md`** (inferred) — only for rules that lack `paths:` but are clearly domain-scoped: `activation_mode: glob` with paths matching the domain:
   - database rules → `["src/**/entities/**/*.ts", "src/**/repositories/**/*.ts"]`
   - multi-tenancy → `["src/**/*.ts"]` (universal) OR `trigger_words: ["tenant", "tenantId"]`
   - AI / Claude integration → `["src/**/claude/**/*.ts", "src/**/prompt-builder/**/*.ts"]`
4. Copy rule content from `.claude/rules/<domain>.md` verbatim (Windsurf doesn't support file includes).
5. **Do NOT port `inject-path-rules.sh`** — it is the Claude-Code-only mechanism for applying `paths:` rules; `activation_mode: glob` is its Windsurf-native equivalent.

## Idempotency

Generator marker at top of file (below frontmatter):
```markdown
<!-- GENERATED BY claude-setup-project. User edits below persist. -->
```

User-owned files: prefix `90-user-*.md` — generator never touches.

## Known gotchas

- **12,000 character cap per rule file.** If a translated rule exceeds this, split it into `10-db-part-1.md`, `10-db-part-2.md`.
- `activation_mode: always` rules burn context on every message — use sparingly.
- `trigger_words` is case-insensitive but requires exact word match (not substring).
- Folder is `.windsurf/rules/` (not `.windsurf-rules/` or `.windsurfrules/`).
- Rule filename is NOT displayed in Windsurf's UI — the frontmatter content + first heading are what users see.

## Full artifact translation

### Commands — `.claude/commands/<name>.md` → `.windsurf/workflows/<name>.md` (NATIVE)

Windsurf Cascade has native slash commands via `.windsurf/workflows/*.md`. The filename (minus `.md`) is the slash command. One file per command:

```markdown
<!-- GENERATED BY claude-setup-project. User edits below persist. -->

# /endpoint-test

<body of .claude/commands/endpoint-test.md>

Arguments: the user's typed args after `/endpoint-test`.
```

User invokes: `/endpoint-test OrderController` in Cascade chat — exactly as in Claude Code.

Path: `.windsurf/workflows/<command-name>.md` (no prefix).

> **Backward-compat**: pre-Apr-2026 setup-project wrote a catalog at `.windsurf/rules/80-commands.md`. Phase 4.8 / 4.8-DEEP keep that catalog as a fallback; new setups should rely on `.windsurf/workflows/` as primary.

### Agents — `.claude/agents/*.md` → `.windsurf/rules/81-agents.md` with `activation_mode: trigger_words`

Best fit for Windsurf's capability:

```markdown
---
activation_mode: trigger_words
trigger_words: ["backend-reviewer", "review backend", "code review"]
---

# Persona: backend-reviewer

<agent body>
```

When user's message contains any trigger word, Cascade auto-loads this persona. Closer to auto-dispatch than most other tools.

One rule file per agent (12k char cap per file means multiple agents won't fit in one).

### Hooks — `.claude/hooks/*.sh` → Cascade hooks (`.windsurf/hooks.json`)

**Native support:** full `✓`. Windsurf Cascade has a native hook system — shell commands fired at key agent lifecycle points, with pre-hook blocking.

**Native mechanism:** **`.windsurf/hooks.json`** (JSON) at repo root (also user-level `~/.codeium/windsurf/hooks.json` and a system-level path; all run system → user → workspace). **12 events:** `pre_read_code`/`post_read_code`, `pre_write_code`/`post_write_code`, `pre_run_command`/`post_run_command`, `pre_mcp_tool_use`/`post_mcp_tool_use`, `pre_user_prompt`, `post_cascade_response`, `post_cascade_response_with_transcript`, `post_setup_worktree`. Each hook gets JSON on **stdin** (`agent_action_name`, `trajectory_id`, `execution_id`, `timestamp`, `model_name`, `tool_info`). **Pre-hooks block by exiting `2`** (stderr → agent); exit `0` proceeds; any other code proceeds with a logged error. Post-hooks cannot block. Use the `command` field (bash) and/or `powershell` field per entry.

```json
{
  "pre_write_code":  [{ "command": ".windsurf/hooks/guard-write.sh" }],
  "post_write_code": [{ "command": ".windsurf/hooks/post-edit-check.sh" }],
  "pre_run_command": [{ "command": ".windsurf/hooks/guard-destructive.sh" }]
}
```

**Translation of the repo's hooks:**
- `guard-destructive.sh` + `pre-edit-guard.sh` + `secret-scan.sh` → **native** `pre_write_code` (block `.env*`/migration edits) + `pre_run_command` (block destructive shell); `exit 2` to deny.
- `post-edit-check.sh` + `format-on-save.sh` + `auto-test.sh` → **native** `post_write_code` — lint/format/test after each edit.
- `inject-path-rules.sh` → keep as **path-scoped activation-mode rules** (`.windsurf/rules/*.md`, `activation_mode: glob`); Cascade hooks block/log but do not inject conversation context.
- `session-start.sh` (SessionStart) → **no session-start event** — nearest is `pre_user_prompt` (fires each turn) or keep the always-apply `00-project.md` "read `ai/status.md`" rule.
- `update-session-log.sh` (Stop) → **native** `post_cascade_response` (fires after each response completes).
- `notify.sh` → **native** `post_cascade_response`, or n/a.

**Caveats:** hooks are block-or-log only — **no context-injection field**, so briefing/path-rule hooks stay as activation-mode rules. `~` home expansion is **not** supported (use absolute paths); working dir defaults to repo root. Windows needs the `powershell` field (the `command` bash field is only a fallback). Repo scripts must be adapted from Claude Code's payload schema to Cascade's stdin JSON + exit-code-2 blocking contract.

**Source:** https://docs.windsurf.com/windsurf/cascade/hooks
