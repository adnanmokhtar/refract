# Baseline — data

Format and verdicts: `README.md` in this directory.

| ID | Standard | Fires when the change… | MET means | Checked by | Source |
|---|---|---|---|---|---|
| DATA-1 | A natural key — email, username, slug, SKU, phone, external/provider id, anything the domain says "there is only one of" — has a **database-level** unique constraint, scoped the way the domain is (per tenant, case-insensitive, soft-delete-aware). | adds or changes an entity, table, column or migration; ports one from V1; adds a create/update path on such a table | the unique index / constraint at `file:line` in the schema or migration, plus a test that inserts a duplicate and asserts the rejection | gate · `standards-check.py` · `@schema-reviewer` | `packs/database/rules/database-principles.md` |
| DATA-2 | A uniqueness violation surfaces as the domain's conflict error (409 / typed error), not a 500. Check-then-insert is a message, never the guard — the constraint is the guard. | adds a write on a table with a unique key | the catch / mapping site at `file:line` and a test asserting the conflict response | gate · `@api-reviewer` | `packs/database/rules/database-principles.md` · `packs/backend/rules/backend-principles.md` (error contract) |
| DATA-3 | Foreign keys declared in the database with an explicit `ON DELETE`. ORM-only relations do not count. | adds a relation | the FK at `file:line` in the migration | gate · `@schema-reviewer` | `packs/database/rules/database-principles.md` |
| DATA-4 | `NOT NULL` by default; nullability is a stated choice. Invariants the app should not re-enforce are `CHECK` constraints. | adds a column | the column definition at `file:line`; a nullable column carries its reason | gate · `@schema-reviewer` | `packs/database/rules/database-principles.md` |
| DATA-5 | Every FK column and every column a new query filters, sorts or joins on has a usable index — verified against the engine (InnoDB creates FK indexes itself; Postgres does not). | adds a query, a FK, or a filter/sort option | the index at `file:line`, or the plan output showing it used | gate · `@query-optimizer` | `packs/database/rules/database-principles.md` · `packs/performance/rules/performance-principles.md` |
| DATA-6 | A use case that writes more than once runs in **one** transaction owned by the service layer, with no external call (HTTP, queue publish, provider API) held inside it. | adds or changes a multi-write use case | the transaction site at `file:line`; external calls outside it | gate · `@api-reviewer` | `packs/backend/rules/backend-principles.md` · `packs/database/rules/database-principles.md` |
| DATA-7 | Contended read-modify-write (balance, stock, counter, seat, sequence, default-flag) is row-locked or version-guarded — never load-mutate-save. | adds an update whose new value depends on the old one | the `FOR UPDATE` / version check / single-statement update at `file:line`, plus a concurrency test | gate · `@api-reviewer` | `packs/database/rules/database-principles.md` · `packs/backend/rules/concurrency-discipline.md` |
| DATA-8 | Schema changes ship only as reviewed migrations — reversible, or with the forward-fix written in the header; breaking changes go expand → backfill → switch → contract. No auto-sync in production. | changes the schema | the migration file; `/migration-review` verdict | gate · `/migration-review` · hook:guard-destructive (`DROP`/`TRUNCATE`) | `packs/database/rules/database-principles.md` |
| DATA-9 | Money is `DECIMAL(p,s)` or integer minor units with a currency — never float. | adds a monetary column or field | the type at `file:line` | gate · `standards-check.py` | `packs/database/rules/database-principles.md` |
| DATA-10 | Every process reaches the database through a bounded pool sized against the server's connection limit. | *project-level*, and when the change adds a DB client, a process type, or changes replica count | the pool config at `file:line` with the arithmetic | gate | `packs/database/rules/database-principles.md` |
| DATA-11 | Tenant and soft-delete filters are applied by construction — base repository, global scope or RLS. A query that bypasses it adds both filters itself and carries a cross-tenant test. | adds a query in a multi-tenant or soft-delete project | the base-repository / RLS site, or the bypass with its test | gate · `/tenant-leak-audit` | `packs/security/rules/security-principles.md` · `packs/database/rules/database-principles.md` |
| DATA-12 | Related reads are batched or joined — no per-row follow-up query; a bulk write is batched or chunked, never one round trip or one unbounded transaction per item set. | adds a list or query path, or a write that scales with the size of a user's selection | the batched read / join at `file:line`, or `n-plus-one-scan` clean on the new path | gate · `n-plus-one-scan` | `packs/performance/rules/performance-principles.md` |
| DATA-13 | A PII column is classified, has a retention window enforced by a real mechanism, and an erasure path that reaches every dependent row — including copies. | adds a column holding personal data, or copies personal data (a name, phone, e-mail) into another table or a JSON / document field | the classification + retention mechanism + erasure path | gate · `@data-privacy-reviewer` | `packs/database/rules/database-principles.md` |
