# Baseline — backend / API

Format and verdicts: `README.md` in this directory.

| ID | Standard | Fires when the change… | MET means | Checked by | Source |
|---|---|---|---|---|---|
| SEC-01 | Untrusted input is validated once, at the boundary, with a schema (`decode → validate → normalize → authorize`), and writes bind an explicit field allow-list — never the whole body. | adds an HTTP / webhook / queue / upload / CLI entry point, or changes what one accepts (a new side effect behind an unchanged input does not fire it) | a validator on every input field, and an invalid-body test asserting the project's validation status | gate · `@api-reviewer` | `packs/backend/rules/backend-principles.md` · `packs/security/rules/security-principles.md` |
| SEC-04 | Authentication on by default; authorization checked after it, per action. | adds an endpoint or an action on one | a **403** denial test for an authenticated-but-unauthorized principal — a 401 alone does not count | gate · `@api-reviewer` · `@auth-reviewer` | `packs/backend/rules/backend-principles.md` · `packs/security/rules/security-principles.md` |
| SEC-02 | A URL fetched on a user's behalf passes an egress allow-list on the resolved IP. | fetches a user-supplied URL | the allow-list site and a test rejecting a metadata / loopback target | gate · `@security-auditor` | `packs/backend/commands/add-endpoint.md` |
| SEC-05 | Configuration is validated at boot and fails fast; secrets come from the environment or a manager, never the repo. | adds a config key or a secret | the config schema at `file:line` | gate · `standards-check.py` · hook:secret-scan | `packs/backend/rules/backend-principles.md` |
| API-7 | Every retry boundary (webhook, queue consumer, payment, client-retried POST) is idempotent: the key is stored and its result replayed atomically with the side effect. | adds a webhook, consumer, payment call, or a POST clients retry | the dedupe constraint + store site, and a replay test proving the second call does not re-execute | gate · `@api-reviewer` | `packs/backend/rules/backend-principles.md` · `packs/distributed-systems/rules/distributed-principles.md` |
| API-8 | Every list endpoint paginates with a default and a hard maximum. | adds a list endpoint | the clamp site and a test that an over-cap `limit` is clamped | gate · `@api-reviewer` | `packs/backend/commands/add-endpoint.md` |
| API-9 | Errors are typed domain errors mapped to one error contract in one place; clients never see stack traces, SQL or paths. | adds an error path | the error class and the single mapping site | gate · `@api-reviewer` | `packs/backend/rules/backend-principles.md` |
| RES-1 | Unauthenticated and expensive endpoints (search, export, report, bulk, upload, LLM proxy) are rate-limited, with counters in a shared store. | adds such an endpoint | the limiter site and a test that the (N+1)-th call is `429` with `Retry-After` | gate · `standards-check.py` (presence) · `@api-reviewer` | `packs/backend/rules/backend-principles.md` · `packs/backend/ai-patterns/rate-limiting.md` |
| RES-3 | Every external call — HTTP, database, cache, queue, provider SDK — has an explicit timeout inside the caller's budget. No-timeout is not a default. | adds a call to another service or provider, or constructs a client / pool (a new query on an existing DB client does not fire it) | the timeout at the call or client site, `file:line` | gate · `standards-check.py` | `packs/distributed-systems/rules/distributed-principles.md` · `packs/backend/rules/backend-principles.md` |
| RES-4 | Retries are bounded, for transient errors only, with exponential backoff **and jitter** — never on a 4xx, never on a non-idempotent write. | adds a retry or an outbound call | the retry policy at `file:line` | gate · `@resilience-reviewer` | `packs/backend/rules/backend-principles.md` · `domains/integrations/rules/integrations-sync-discipline.md` |
| RES-2 | Outbound resilience past timeout and retry — circuit breaker, bulkhead, fallback, DLQ — where the call can cascade. | adds a call to another service or a provider on the request path | the breaker / fallback site, or `n-a` with the reason it cannot cascade | gate · `@resilience-reviewer` | `packs/distributed-systems/rules/distributed-principles.md` |
| RES-5 | Graceful shutdown: stop accepting, drain in-flight work, finish or requeue jobs, close pools — bounded by a deadline. | *project-level*, and when the change adds a server entry point, worker or consumer | the signal handler at `file:line` | gate · `standards-check.py` (presence) | `packs/backend/rules/backend-principles.md` |
| RES-6 | Queue consumers, schedulers and CPU-heavy work run in a worker process, not in the process serving requests; a slow job never shares an event loop with a request. | adds a job, consumer, cron, or CPU-bound task | the worker entry point and its process / deploy definition | gate | `packs/backend/rules/backend-principles.md` · `domains/background-jobs/rules/job-design.md` |
| OBS-4 | Liveness and readiness endpoints; readiness pings each declared dependency rather than returning a bare 200. | *project-level*, and when the change adds a service or a hard dependency | the readiness handler at `file:line` | gate · `standards-check.py` (presence) · `@api-reviewer` | `packs/backend/agents/api-reviewer.md` · `packs/distributed-systems/rules/distributed-principles.md` |
| OBS-1 | Each endpoint emits rate, errors and a duration histogram, and a trace span; the correlation id propagates through every layer and downstream call. | adds an endpoint, or a call to another service | each signal matched to a line emitted in the diff, or to the auto-instrumentation site that emits it | gate · `@observability-reviewer` | `packs/backend/rules/backend-principles.md` · `packs/observability/rules/observability-principles.md` |
| OBS-5 | Logs are structured, carry the correlation id, and never contain secrets, tokens or full PII. | adds log lines (application logs — product audit / activity rows are SEC-06) | the logger call sites | gate · `standards-check.py` (no console.log) · hook:secret-scan (credentials only) | `packs/backend/rules/backend-principles.md` · `packs/observability/rules/observability-principles.md` |
| PERF-6 | Request-scoped or per-user state — sessions, caches, rate counters, locks, dedupe sets — lives in a shared store, never process memory or local disk. | adds any of those | the shared-store client site | gate | `packs/backend/rules/backend-principles.md` |
| SEC-06 | An audit / activity / history row names the authenticated actor and takes every field from server-authoritative data — never from the request body — and commits in the same transaction as the change it records. | adds or changes an audit, activity or history record | the actor taken from the session / principal, the fields read server-side, the write inside the change's transaction — each at `file:line` | gate · `@security-auditor` | `packs/security/rules/security-principles.md` (audit log) |
| API-10 | User-facing text the server produces goes through i18n keys, or the server returns codes and parameters the client translates. | adds or changes text a user will read that the server generates | the key or code at `file:line`, present in every declared locale | gate | `packs/frontend/rules/frontend-principles.md` (i18n) |
| API-11 | A changed response on an existing endpoint is additive or versioned, and every consumer and contract test is updated in the same change. | changes the shape or meaning of an existing endpoint's response | the additive field / version, and the consumer + contract-test updates | gate · `@api-reviewer` · `contract-test` | `packs/backend/ai-patterns/api-contract.md` |
| PERF-7 | Every cache entry has a TTL or an explicit invalidation path; the key includes every identity the value depends on (tenant, user, permission); hot keys are stampede-protected. | adds a cache read or write | key builder, TTL and invalidation site | gate · `/probe-cache` | `packs/performance/rules/performance-principles.md` · `domains/caching/rules/caching-discipline.md` |
